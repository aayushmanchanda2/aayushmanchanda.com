# design.md

The design contract for this site, written from the shipped code. Read it before touching UI. Every claim names the file and the selector or symbol that enforces it, so any of it can be checked with one grep. **If the code and this file disagree, fix whichever is wrong, in the same commit.**

Paths are relative to `src/`. `file › thing` means "grep for `thing` in that file".

**`/design` is the public half of this file**, and it is the half you can press. It renders the mark, the tokens, the type scale, the chips, the link styles and the press states using the shipped components and the live stylesheet, so it cannot describe a system the site does not have. When a rule below changes, open that page: if it still shows the old thing, the rule did not actually land.

The text, surface and border values are briOS's (brianlovin.com, measured live for VET-225), down to the dark theme's pure black page. The surfaces are declared for raised rows and panels. **A selected list row is `--surface-selected` plus `--shadow-contrast`** (VET-240, briOS's /hn list, `HNLayoutClient.tsx`): neutral 100 in light with no shadow, neutral 900 in dark with the half-pixel inset highlight, because a flat fill on a black page reads as a hole rather than a raised row. Hover paints the same pair, as briOS's does. The /library pane is the consumer (§3). `lib/theme.test.mjs` holds the two dark blocks to each other, and `lib/ink.test.mjs` fails if any token the dark theme sets has no light value.

**Light is the base; dark is declared twice.** The theme is three-state — follow the OS, or pin light, or pin dark — and it lives in one place at runtime, `data-theme` on `<html>`, always carrying one of `system` / `light` / `dark`. **With nothing stored, it is `system`**: `lib/theme.ts › PREPAINT` writes it before first paint, so a reader on a dark OS gets dark on the first frame and a press on the toggle is what pins a theme. Light is plain `:root`, so it is what a page is with no attribute, no media query and no scripting. Dark then has to arrive from two directions, and both blocks must declare **exactly** the same properties with the same values:

```css
:root { /* light: the base */ }
@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { /* dark */ } }
:root[data-theme="dark"] { /* dark, again, identically */ }
```

The `:not()` is what lets a pinned light theme win on a dark OS, and `system` matches it on purpose. CSS has no way to say a block twice without writing it twice, so `lib/theme.test.mjs` parses `global.css` and `chip.css`, keys every dark rule by its selector with the guard stripped off, and fails if the two sets differ by a property, a value or a selector — or if a rule inside the media query forgets its guard. **Add a token to one block, add it to the other.** The failure it exists to catch is silent: a token declared only under `prefers-color-scheme` looks right to everyone whose OS is already dark, and ships a half-themed page to everyone who pinned dark on a light machine.

Everything else derives. `palette.css` has no theme-conditional declaration at all and must keep it that way; the same test asserts it. The only other theme-conditional thing in the build is the pair of `theme-color` metas, which JS re-points by rewriting their `media` to `all` / `not all` when a theme is pinned (`lib/theme.ts › THEME_COLOR_MEDIA`), because a browser resolves those queries against the OS and not against us.

**The accent is one hue at two lightnesses**, `hsl(231 100% 58.4%)` and `hsl(231 100% 68%)`. Hue is identical across themes; lightness is the only difference, because no single lightness clears 4.5:1 against both `#FFFFFF` and `#000000`. Measured: `#2B4BFF` on white is 5.91:1, `#5C74FF` on `#000000` is 5.40:1. Both AA for normal text.

**`--accent` vs `--accent-panel`.** `--accent` is for ink: links, hover, `aria-current`, focus rings. The moment the accent becomes a *background with text on it*, switch to `--accent-panel` (`#2b4bff`, held at the vivid blue in **both** themes) with `--accent-panel-ink` (`#ffffff`). White on the dark theme's `--accent` is **3.89:1 and fails AA**; white on `--accent-panel` is 5.91:1 either way. In force at `MobileNav.astro › .mnav__panel`, `styles/palette.css › .palette__row[data-active]`, `layouts/Base.astro › .skip`.

**Selection is a tint, not a fill** (`styles/global.css › ::selection`, `--selection-bg` / `--selection-ink`). Light keeps the accent at 18% under primary ink, 13.58:1; briOS's light pair (`rgba(0,154,250,.1)` under `#0066db`) is 4.80:1 and puts a second blue on a page whose links are ours, so it was not taken. Dark takes briOS's orange pair exactly: `#ff6b01` over `rgb(240 104 0 / .1)` is 6.79:1 on the page and 4.67:1 over `--surface-3`, the darkest ground a selection can land on. Measured on the page with `getComputedStyle(el, "::selection")` (VET-240 evidence).

**Amber is the second accent, and it marks things; it is never a link or a control** (VET-240). Three consumers: the amber chip tone (the `on-hold` verdict, the `video` kind, the `paused` status: `chip.css › .chip[data-tone="amber"]`, briOS's `PlatformBadge` pair), `<mark>` (`global.css › mark`, the highlighter; inked by whatever it sits in), and dark `::selection` above. An accent-bar variant was asked for and not built: nothing would use it until the doodle work (J1) does. Contrast over the page and over `--surface-3`, held by `lib/ink.test.mjs › PAIRS`:

| Pair | Light | Dark | Floor |
|---|---|---|---|
| `--amber-ink` on `--amber-bg` | 6.84 | 12.66 (10.68 on `#171717`) | 6:1, the chip bar |
| `--text-primary` on `--highlight` | 13.93 | 9.47 | AA |
| `--text-primary` on `--highlight-blue` / `-pink` / `-green` | held by `ink.test` | held by `ink.test` | AA |
| `--selection-ink` on `--selection-bg` | 13.58 | 6.79 (4.67 on `--surface-3`) | AA |

The dark highlighter drops to 30% because the light value's 45% under white-at-.9 ink is 6.13:1 and reads as a lit panel rather than a pen stroke. `--text-tertiary` on the highlighter is 3.69 / 4.11, which is why a mark goes on reading text and not on meta.

**Chip tones** (`styles/chip.css`). A tone sets three numbers and the tint, the hairline and the ink all derive from them, so light and dark stay in step without a second palette. Soft tint, never a solid fill: twenty rows should read as one page, not a traffic light.

**Every ink clears 6:1 over its own tint** — over the colour the tint composites to, not over the bare page background. That distinction is the measurement. The tint lightens the ground in the light theme and darkens it in the dark one, so ink-over-tint is always the lower of the two numbers and it is the one a reader is actually subject to; measuring against the page flatters every tone by roughly 0.8 of a point. Four values were set from the page-background reading and did not in fact hold over their own tint — light green 5.59, light amber 5.44, light gray 5.48, dark blue 5.73 — and are corrected below. The tint alphas did not move, so the fills are unchanged; only the ink deepened, by two or three points of lightness.

| Tone | Light `h s l` | ink/tint | Dark `h s l` | ink/tint (on `#000`) |
|---|---|---|---|---|
| green | `148 65% 24%` | 6.20 | `148 55% 64%` | 9.68 |
| amber | `--amber-ink` on `--amber-bg` (tokens, not three numbers) | 6.84 | same tokens | 12.66 |
| gray | `0 0% 35%` | 6.13 | `0 0% 62%` | 6.75 |
| red | `0 70% 38%` | 6.45 | `0 80% 70%` | 6.53 |
| blue | `231 80% 45%` | 7.49 | `231 100% 75%` | 6.50 |

The `.chip--link` hover deepens the tint to 20% / 26%, which costs about a point: that state holds **AA (4.5:1)**, not 6:1. The floor there is light gray at 5.18.

**Chips are pills** (`--r-pill`, VET-225), and **verdicts take briOS's mapping**: `using` green, `watching` blue, `on-hold` amber, `skipped` gray (`VerdictBadge.astro › TONES`). Skipped was red, which read as a warning about the tool rather than a note that he passed on it. The `.chip` block's own fallback lightness is kept identical to the gray tone so an untoned chip and a gray one cannot drift apart.

Tint `0.09` light / `0.14` dark; hairline `0.2` / `0.26`. A `.chip--link` deepens both on hover instead of changing colour. Blue is the accent hue held back from the accent lightness on purpose: an inline link and a shipped chip must not be the same blue on the same page. Held back by two dials in the light theme (saturation 80 against the accent's 100, lightness 45 against 58.4) and by lightness alone in the dark one, where nothing darker than the link blue survives the tint. Measured separation, CIE76: 14.7 light, 22.2 dark — the dark pair is the wider of the two, so the tighter-looking lightness gap there is not the problem it reads as on paper. Which word earns which tone is the only thing the components decide — `VerdictBadge.astro › TONES`, `StatusChip.astro › TONES` — and both are `Record<T, string>`, so a new verdict or status will not compile until it has a tone.

**A tag is a plain grey box: no tone, no hue, no mark** (`styles/chip.css › .tag`, VET-219). A /library tag names a subject, and a subject is not a position on a scale, so it takes no fill. It is ibelick/ui-skills' TopicTag (`src/ui/topic-tag.astro`) one step down: **28px** tall (`1.75rem`; theirs is `h-8`, 32px, and a library row is denser), `0 0.625rem` padding, a **solid 1px `--hairline-strong`** border, **`--r-md` (8px)** corners, Geist sans at `0.8125rem`/500 with normal tracking and no case transform, words at `--text-primary`, transparent ground. Hover fills `--hairline`; `aria-current="page"` inks the border `--text-primary` and the word `--accent`. On the filter row each chip carries its entry count after the label (`.tag__count`), `--text-secondary` (§4's ink floor: it is text inside a control) and `tabular-nums`, `0.375rem` (6px) apart, as TopicTag does.

**It went dot, then hued outline, then plain, and the last reversal is Aayush's** (VET-60 drew a 6px hued dot, VET-67 a dotted seven-hue outline with a drawn mark per tag, VET-219 took both off). The seven hues and the hand-drawn marks read as decoration, and the mark table was a hand edit per new Raindrop word: an undrawn tag held the publish pipeline for four days in September. The word is what a reader scans for, so nothing else on the chip competes with it. `lib/tags.test.mjs` fails if a `.tag` rule reads the hue table again or a dot or mark comes back.

**The tag and the chip are no longer the same height.** A `.chip` stays 20.28px and a tag is 28px; on a `/library/<slug>` strip they sit on one centred line, and both claim a 40px target (§4).

**The identity palette is a hash and the lightness is a measurement.** `lib/tags.ts › hueSlot` folds a key (the poster's x.com handle, for the post monogram) through djb2 into `[0, 7)`; the stylesheet decides what those seven numbers are worth, because a colour typed outside `styles/` is the bug this section opens with. The same handle gets the same hue on every build, which `lib/tags.test.mjs` holds by writing a fixed corpus out.

Hue is identical across themes and lightness is the only difference, the same shape the accent takes above. Every hue clears **7:1 over its own page background** — not the 3:1 a non-text graphic owes, but the band the chip inks already sit in (6.98 to 8.76 light, 7.11 to 11.36 dark), because a monogram and a chip on one page have to read as one weight of colour and 3:1 would have put a pastel next to them.

| 0 | 8 | `38.5%` | 6.95 | `65.5%` | 6.98 |
| 1 | 45 | `26%` | 6.99 | `44.5%` | 6.96 |

**That table is the site's identity palette, and since VET-219 it has one shape.** `styles/chip.css › [data-hue]` sets `--hue-h` and `--hue-l`, and a `.monogram` spends them on a 48px circle and the initial inside it, or on a squircle for a /tools letter tile (`AppIcon.astro`, keyed on the tool's slug, §5). It is keyed on the attribute rather than on the class, so any second consumer reads the same table rather than a copy; `tags.test.mjs` sweeps `[data-hue="N"]` for that reason.

**The monogram is the avatar slot with no avatar in it** (`components/PostCard.astro`, painted at `chip.css › .monogram`, sized to 40px there). Since VET-244 a post carries its poster's real avatar, fetched once at publish time into `/posts/<id>/avatar.webp` (`pipeline/post.mjs`), so the letter is the fallback for a post read before that, hued off the handle.

**Its tint is `0.09` in both themes, which is the one place a coloured thing here does not deepen for the dark.** A chip does because its ink lightens and a 9% wash vanishes under a light ink at pill size; a monogram is forty times the area and does not need the help, and holding it there is what keeps the initial over the 6:1 bar both ways. Measured over its own tint, worst slot: **6.04** light, **6.34** dark. At the chip's 0.14 the dark floor drops to 5.90.

The gap between 192 and 285 is the accent's and it is deliberate: a hue in the 231 band would read as a link marker on a page whose links are that blue. **Seven hues collide often across handles, and that is accepted** — the name beside the monogram is the identifier, and nothing here is ever named by colour alone.

**Hairlines.** `--hairline` (9% alpha) rules every border on the site. `--hairline-strong` (12%) is the hover state of a row border, a control's outline and the inset edge of a swatch. There is no third weight. Both are plain black or white at alpha, not derived from the text colour.

**Dotted grid.** `styles/global.css › .dotted-grid`: `radial-gradient(var(--dot) 1px, transparent 1px)` at 16px, `--fine` at 10px. It is the backdrop for framed imagery only (`ShotFrame.astro`, `ImageFrame.astro`), never a page texture.

**Motion + layout.** `--ease` `cubic-bezier(.22,1,.36,1)`, `--ease-out` `cubic-bezier(.16,1,.3,1)`; `--dur-fast` 120ms, `--dur` 220ms, `--dur-slow` 420ms. `--page-max` 42rem (the reading column, and the footer everywhere), `--page-pad` `clamp(1rem, 5vw, 3rem)` (24 / 32 / 48px on a full-width page, §3), `--bar-h` 3.5rem (the top bar), `--gap-masthead` `clamp(3.5rem, 12vh, 6rem)` (2.5rem on a full-width page), `--mat-w` `clamp(0.5rem, 0.8vw + 0.35rem, 1rem)` (the mat round the stamp: 8.7px at 390, 15.8px at 1280, 16px max; VET-262), `--band` `clamp(0.625rem, 0.5vw + 0.5rem, 0.875rem)` (the stamp's white margin, perforation to keyline: 10px at 390, 14px from 1280), `--frame` `calc(var(--mat-w) + var(--band))` (the content's inset, which everything pinned under the bar reads: 18.7px at 390, 29.8px at 1280), `--grain` (arc.net's film grain as an `feTurbulence` data URI, on the mat and the menu panel), `--mat` (the mat under the stamp, per section, `styles/frame.css`; the `theme-color` metas keep the old neutral paper, `lib/theme.ts › THEME_COLORS`). Radii: `--r-sm` 4px (focus ring, key caps), `--r-md` 8px (the tag and the hover preview card), `--r-lg` 12px (hovered, focused and selected rows: the /tools grid tile's hover, a /tools row's focus ring, a /library pane row) and `--r-pill` (chips and the accent bar) are the whole *corner* scale (see §3).

**`--gap-masthead` is the space under a masthead**, before whatever the page is about — every section index, every filter page, `/design`, the 404 and the three `.doc` pages, fourteen surfaces in all. It was the same `clamp()` written out fourteen times in fourteen scoped style blocks, which is a number nobody can retune: changing it meant finding all fourteen, and the one that got missed would be the page nobody had open. Note that these layout tokens are not on `/design` — that page's table reads colour tokens through `getComputedStyle`, and a length has no swatch to paint.

## 2. Type

Geist Sans for prose, labels and dates; Geist Mono for data: counts, clocks, hex values, key caps and code. Both are variable fonts bundled from npm and served from our own origin; the site loads nothing from a third-party CDN (`layouts/Base.astro › @fontsource-variable`).

**Bold, not big** (VET-225, briOS's system, Aayush's call). Titles carry weight 700 at a size that leaves room for the page: the section masthead tops out at 56px (it was 84px), the entry title at 40px. Everything under them is calm.

**The label voice.** `styles/global.css › .mono` is **Geist Sans at `0.875rem` (14px), weight 400, `letter-spacing: normal`, no case transform** (14px/400 since VET-225, briOS's meta size; it was 13px/500): ui-skills' own rule, *"Use sentence case for labels and links"* (`DESIGN.md`). It is every section head, field label (`dt`), crumb, tab, strip, footer item, clock name and hint row on the site. Source text is written in sentence case (`Saved copy`, `As of`, `Source`), because nothing in the stylesheet changes its case any more. It was 11px uppercase mono at `0.08em` (section heads opened to `0.1em`) until VET-223, and the class keeps the name: ninety call sites and the tests that read them match it, and a rename would be a diff about a word. A tag (`chip.css › .tag`) was already this voice, so a tag and the words beside it on an entry strip are now one voice.

**Dates are words, in a `<time>`.** Every date on the site prints as `Aug 13, 2026` inside `<time datetime="2026-08-13">`, through one helper, `lib/date.ts › formatDay` (UTC both ends, so the build machine's zone never moves the day). The ISO string stays the machine value and the `datetime`; the words are what a reader sees: `Saved <time datetime="2026-09-22">Sep 22, 2026</time>`. Dates are sans and carry no `.tabular-nums`.

**Mono is kept for data, and the switch is `.tabular-nums`.** Inside the label voice, `.mono.tabular-nums` and `.mono .tabular-nums` set Geist Mono. Every figure that changes in place or sits in a column carries that class (below), so a count, a clock or a year goes mono with no second opt-in. Kept mono, and why:

| Where | Why mono |
|---|---|
| tab, segment and group counts (`KindSegments.astro › .seg__count`, the /tools filter count in `tools.astro › .count`), the index numbers, the 404 counts | figures in a column |
| the footer clocks and the copyright year | digits that change in place |
| key caps: `esc`, `←`, `→`, `⌘K`, the palette's `Esc` (`EntryNav.astro › .hint__key`, `Footer.astro › .foot__search kbd`, `palette.css › .palette__esc`) | a literal printed on the keyboard |
| a hex (`PaletteRow.astro › .swatch__hex`), a token value in a site's design panel (`SiteFoundations.astro › .row__value`), a token or class name on `/design` (`design.astro › .code`), a command in a voice block (`VoiceBlocks.astro › .voice__body--code`) | code; it has to read exactly as it will arrive |
| the kind and verdict chips (`chip.css › .chip`) | their own component voice, 12px lowercase mono, not a label (11px until the Wave A QA: under the 12px floor) |

**Domains are sans.** A hostname in a row's meta column or on an entry strip reads cleanly in lowercase sans at 14px, beside a date that is sans too. The same goes for a post's `@handle`.

> **A `<button>` gets `mono` on itself, never through its container.** `styles/global.css › button` resets `font` to inherit, but the UA stylesheet still owns a form control's other text properties. Under the old uppercase voice that shipped a bug: the footer's `Search` was the one colophon item not shouting like its four neighbours. The new voice sets `letter-spacing: normal` and no transform, which is what the UA sets too, so the difference no longer shows; the rule stays because it costs nothing and the next voice change could bring it back. Every label-voice button carries the class directly (`ShotActions.astro › .act`, `MobileNav.astro › .mnav__search`, `NewsletterSignup.astro › .news__submit`, `Footer.astro › .foot__search`, `tools.astro › .views__btn`).

**Four text levels, and every piece of text is one of them** (briOS's, VET-225). Declared beside the tokens in `styles/global.css › :root` and rendered as a specimen on `/design`. Contrast on the page background, measured and held by `lib/ink.test.mjs`:

| Level | Token | Light / dark | For |
|---|---|---|---|
| primary | `--text-primary` | 17.93 / 16.75 | titles, **long-form prose**, names, links, a tag's word, a facts value |
| secondary | `--text-secondary` | 7.81 / 9.96 | standfirsts, row notes, **and every control** (§4's ink floor) |
| tertiary | `--text-tertiary` | 4.74 / 5.28 | meta: labels, dates, counts, captions |
| quaternary | `--text-quaternary` | 2.52 / 2.67 | decoration only: the crumb divider, never a word |

Meta at `--text-tertiary` now clears AA (it was 2.94:1 at 45% alpha and 13px). Anything a reader presses sits at `--text-secondary` or above. The VET-223 audit found two strays and fixed them: the collection links on `/sites` inherited the label's `--text-tertiary` (`sites.astro › .collections a`, now `--text-secondary` and held by `lib/ink.test.mjs`), and a quotation in a note body was prose at `--text-tertiary` (`notes/[slug].astro › .prose blockquote`, now `--text-secondary`). One stated exception: the draft block's label is `--text-primary` on purpose (`DraftBlock.astro › .draft__label`), because it is the one label whose job is to be read before the box under it.

**Spacing rhythm: 8, 16, 40.** **8px (`0.5rem`) inside a group**: a label and its value, a row's name, chip and note, the items in a meta column, a separator row's items. **16px (`1rem`) between groups**: a title and its metadata strip, the strip and the standfirst, the tabs, the tag filters and the list on /library, one list row and the next (padding either side of the rule), two voice or digest blocks. **40px (`2.5rem`) between sections**: the embed, the saved copy, the digest, the voice blocks, the source line, the facts table and the hint row on an entry page. The masthead gap (`--gap-masthead`) and the `.page-title` margins are not part of it; they are the titles' own air. **Hit-area arithmetic outranks the rhythm**: a tag row's `0.75rem` gap and the /library entry strip's `1.25rem` row gap are 40px targets being kept apart (§4), and `lib/tags.test.mjs` holds them.

**Tabular numbers are not optional.** Any digit that changes in place, or sits in a column, gets `.tabular-nums`: the footer clocks, group counts, the index row numbers, the copyright year. Dates are not on the list: they are words (above), and the class would set their digits in mono. Put the class on the figure and not on the phrase around it, because inside the label voice it is also what sets the figure in mono.

Headings are 600 / lh 1.05 / `-0.03em` with `text-wrap: balance`; paragraphs get `text-wrap: pretty`. Both are already global — do not re-declare them. The masthead classes above override the weight to 700.

**Two text sizes do the work: 14px for UI, 16 to 18px for reading** (VET-240, briOS's rhythm). A row in a list or a table is UI: 14px at 1.45, title at 500, meta at `--text-tertiary`, no negative tracking (tracking tightens display sizes, not 14px). Body text is 16px/1.6 and prose 18px/1.6. Three lists keep a display size on purpose and are not UI rows: the /notes list and "Read next" (`EntryList.astro`, 20px, briOS's /writing `text-xl`), "Latest" (18px), and the home section index, whose names are 22 to 28px headings. The /tools grid's 13px label is a springboard label and stays until the home-screen work (J3). A 15px size existed in five places and belonged to neither tier; it is gone from every row.

**Nothing is smoothed and nothing is synthesised** (`global.css › body`). `-webkit-font-smoothing` is left at the platform default, briOS's `subpixel-antialiased`: `antialiased` thinned Geist on macOS everywhere, and the fix used to be applied to prose alone, so a 14px row was thinner than the paragraph beside it. `font-synthesis-weight: none` stops a browser inventing a bold Geist does not ship. `text-rendering: optimizeLegibility` was considered for prose and not added: kerning is already on at every size in the engines we ship to, and the property's other effect is slower layout on long pages.

**`.prose` means reading text** (`styles/prose.css`, VET-229, values from briOS's `renderBlocks.tsx` and `globals.css › .prose`): any body a reader reads top to bottom, a note's markdown or an entry page's saved copy, digest and voice blocks alike. Put it on the element that wraps the body (`<Content />` on a note); the page adds only its own margin. Blocks sit **16px** apart. Lists indent `1.75em`, items **8px** apart, markers at `--text-tertiary` (furniture, not words; a nested list goes to circles), so a bulleted "first impressions" note reads as ten lines rather than ten dots. A blockquote is `--text-secondary` behind a 3px `--hairline-strong` rule. Inline code is mono at `0.875em` on `--surface-3` with `--r-sm`; a `pre` is the same surface in a `--hairline-strong` box, `--r-md`, `1rem` padding, scrolling sideways rather than wrapping. **No syntax colour**: `astro.config.mjs` sets `markdown.syntaxHighlight: false`, because Shiki paints an inline `github-dark` background no stylesheet can theme. Images take `--r-md`. The link rule stays in `global.css`'s shared selector list (§5).

**Measures, in rem.** Geist's `1ch` is wider than its average glyph, so a `65ch` cap ran to about 90 characters a line. Note prose and `.doc` **40rem** (about 75 characters at 18px). Standfirst **46ch** (`styles/global.css › .standfirst`). The bodies on an entry page (a post's saved copy, the digest, a voice block) are `.prose` too since VET-231, so **40rem** as well. The column itself **42rem** (`--page-max`).

**The accent bar** (`styles/global.css › .accent-bar`): a 20×4px accent pill drawn above a small section heading, briOS's "Read next" marker. Put the class on the heading. The class is the heading's whole style, 16px/400 `--text-tertiary` at 1.6, so its two consumers, "Read next" under a note and "Latest" on the home page, carry no heading CSS of their own.

Optical corrections in force: the masthead pulls `-0.04em` left so the first stem is flush with the column edge, and `--mono` sets that back to 0 because mono has no side bearing to correct for. Metadata columns used to take a `0.2rem` padding-top to line up with a 17px name; since VET-240 the name and the meta are both 14px at 1.45 and share a first line, so the correction is gone.

## 3. Structure

**The stamp frame** (`styles/frame.css`, VET-255) **on a cutting mat** (VET-260). Every page is a sheet of paper inset `--mat-w` from the viewport, and the sheet's edge is perforated like a postage stamp: half-circles `clamp(6px, --mat-w / 2, 8px)` across on a 1.2× pitch, centred on the edge so half of each bites into the page, spread with `background-repeat: space` so both ends of an edge match. Under it is a mat whose colour names the section: `data-section` on `<html>` (`Base.astro`: the nav section's slug, `home`, or `other`) picks the mat's colours (VET-261, after arc.net): a two-stop `linear-gradient(160deg, --mat-hi, --mat)` within one hue, emerald on /tools, electric blue on /sites, tangerine on /library, violet on /notes, a warm graphite everywhere else, each stop an oklch `light-dark()` pair (dark keeps the chroma and drops the lightness) that resolves off the `color-scheme` both dark blocks already set. Over it sits `--grain` (global.css), arc.net's film grain rebuilt as an `feTurbulence` data URI: a static 220px tile of white specks at 0 to 18% alpha, mean 6.5%, normal blending, matched to arc's `/noise-light.png` (mean 16.5/255, max 41). Fixed and static, so it never repaints on scroll: the VET-260 probe (`qa/evidence/2026-09-23-vet-260/perf.mjs`) records one mat invalidation, its own control, across a two-second scroll. The pattern is a cutting mat (Aayush's pick of three, VET-260): 8px minor and 40px major lines in white tinted toward the mat's hue (`--mat-h`), ruler ticks 5.5px (major) and 2.5px (minor) on the top and left edges, and an 8px Geist Mono digit at 32% on every major line, 3px in (letter-spaced to exactly 40px; hidden under 1024px, where the mat is under 14px). `body` pads by `--frame`, and everything pinned under the bar adds it (`TopBar`, `ToolList`'s header, `SitePanel`, `LibraryPane`, the shell's min-height). The VET-255 and VET-260 audits have the shots. Static, so reduced motion has nothing to change.

A change `replaceState`s, so Back still means the previous entry, and an unknown value reads as All. Nothing matching shows "No entries match both filters. Show all". **The pane is one tab stop**: a roving tabindex puts `tabindex=0` on the `aria-current` row (or the first shown row, when the filter hides it) and `-1` on the rest, so Tab from the top reaches the entry in 7 presses instead of walking 139 links. Up and Down move focus one shown row (stopping at the ends; a filtered-out row is skipped), Home and End jump, Enter is the link's own, and `tabindex=0` follows focus (`lib/library-pane.ts › paneStep`). The skip link is untouched and stays the first stop. It repeats on every entry page, so the markup is three bare elements per row and the style block is global under `.pane`; the cost is written up in the VET-231 audit (about +36KB raw, +6.5KB gzipped per page).

**The site mark** is his initials, **AM**, drawn on the same 16-unit grid as the icon system, `currentColor`. One stroke weight throughout (1.5), and every diagonal in it runs at one angle, 27.8° off vertical. `components/MarkGlyph.astro` is the drawing and nothing else. It sat fixed at the top left of every page as `SiteMark.astro` until VET-225, when the top bar's home link took that job; it is now drawn on `/design`, the favicon and the card. **A page that wants the mark imports `MarkGlyph`**, and `lib/mark.test.mjs` fails on any other file in `src/` drawing a `<path>` of its own.

**The A is the drawing that shipped before it, unchanged to the decimal.** The M is built to that A's *ink* metrics rather than its centreline ones, which is the only way two stroked letters can be made to share a cap line: stems flat at 1.7, so the A's mitred apex tip (1.492) stands above them by 1.7% of cap height, the overshoot a point takes over a flat cap in any real face; stems flat on 14.1, which is where the A's foot centreline lands; and a valley that is the A's apex reflected, same 55.6° included angle and same 2.144 miter ratio, with its tip on 14.4498, the A's own lowest ink.

**Nothing in the mark touches anything.** The crossbar is 0.5 units off the legs and the M is 0.5 units off the A, both measured at the tightest point, which for the letterfit is the outer corner of the A's right foot. It is a monogram held together by proximity rather than by contact, which is also what makes the mark separable, which is what the favicon needs.

`stroke-miterlimit="2.4"` on the M is the one attribute doing work. The A's apex and the M's valley are 2.144 ratios and stay points; the M's two top corners are 4.163 — a 3.1-unit spike out of the top of the box — and are cut flat, which is what a geometric sans does at that junction.

**The favicon is the A alone, and that is a measurement rather than a preference.** Rasterised into 16x16 the lockup has no fully inked pixel in it at all: its strokes land at 0.81 device pixels, peak ink 87%, against the A alone's eighteen pixels at 100%. Four other AM constructions were drawn and every one failed the same way; the only one that kept solid ink at 16px bought it by being square and stopped reading as two letters. So `public/favicon.svg` and `public/favicon.ico` carry the A, the page and the card carry the lockup, and the A lifts out of the lockup whole rather than as a fragment, because nothing in there touches it.

**The left bearing is 0.096 of the mark's height.** The leftmost ink is the outer corner of the A's left foot, 1.5366 of 16 units. `scripts/og.mjs` pulls the mark left by that much plus the `h1`'s own `-0.04em` where the two share a column, and the card's mark needs `align-self: flex-start` now that it is no longer a square box — a column flex default of `stretch` on an `auto`-width SVG centres the glyph across the whole card.

The A's two paths live in three files (`MarkGlyph.astro`, `public/favicon.svg`, `scripts/og.mjs`) and the M's path in two. `lib/mark.test.mjs` compares every copy and fails on a moved point, on a second stroke weight anywhere in the mark, or on an M appearing in the favicon, naming the reason in the message. `npm run og` regenerates the card and the raster icon from the copy in that script.

> **Never spell a CSS custom property inside `public/favicon.svg`'s comment.** XML forbids a double hyphen anywhere in a comment, so a token written with its two leading hyphens makes the file fail to parse and the browser draws a broken image instead of the mark. **This shipped, and nothing caught it**: a tab strip with no icon in it looks like a tab strip, and every other surface draws the mark from the component. It surfaced the first time `/design` rendered the real file on a page at 64px. `lib/mark.test.mjs` now fails on a `--` inside any comment in that file. The general shape of the lesson is the reason `/design` exists at all: **an asset nothing renders on a page is an asset nobody is checking.**

**The colophon is the footer, not the nav.** `/about`, `/contact`, `/design` and `/privacy` are the four pages about the site rather than in it, and all four live in `components/Footer.astro › .foot__meta` — the links at `--text-secondary` (§4's ink floor: they are controls), the separators and the copyright at the row's `--text-tertiary` — in that order: the two about the person first, because that is what most readers are looking for down there, then the two about the machinery, with `/privacy` last because nobody comes looking for it until they need it. The nav — the menu panel — stays the five content sections, which is what `lib/sections.ts` enumerates and what the empty-section rule governs; none of the four appears there, in `getSections`, or in a markdown variant. `.foot__meta` wraps: five items is wider than a 375px column, and an unwrapped flex row pushes the last one off the side rather than dropping it to a second line.

**The footer is three centred groups, and the centring is the thing that makes them three.** `components/Footer.astro › .foot` is a flex *column*: `.foot__row` (the two profile links, the two clocks, the theme toggle), then `.foot__meta` (the palette and the four colophon pages), then `.foot__legal` (`© {year} Aayush Manchanda`, its own line, `tabular-nums` like every other digit that changes in place). Everything above the footer on this site is flush left and stays that way — the footer is the one block that is not content but a colophon closing it, and centring is what says so.

It was one wrapped row, and the row had come apart: the links sat left, an `auto` margin pushed the clocks right, and the colophon wrapped underneath at the left edge again, so three groups took three different alignments. **The gap between the groups is what separates them, and it is deliberately not a token.** `--gap-masthead` is the space *under a masthead*, 3.5 to 6rem, and far too much air at the foot of a page; `.foot__meta` takes a flat `2rem` and `.foot__legal` `0.85rem`, tight against the colophon because the copyright is that group's tail rather than a fourth group. `--gap-masthead` earned a token by being written out fourteen times in fourteen scoped blocks; two numbers in one file are retunable by opening the file, and a token with one consumer is indirection bought for nothing.

Below 599px the column is narrow, and two things there do not survive the move unchanged. The clocks take a line to themselves (`order: 1`, `flex-basis: 100%`), because three items sharing one wrapped row centre as *pairs*: the clocks came out left of centre with the theme toggle riding beside them. That reorder costs nothing in tab order — a `dl` of readouts has nothing focusable in it, so the only two stops are the links and the toggle and they still run left to right. And `.foot__meta` takes a `16rem` cap and, at that width, no dots (a `1rem` gap separates), because five items and four separators were 283px of the 287 available: the row filled its line to within 2px and dropped `Privacy` alone onto a second one, which is centred but with no air either side to show for it, so it read as a line that had been cut off. The narrower box is what makes the wrap deliberate — three items, then two — instead of leaving it to whether a glyph is a pixel wider today.

**The X mark is drawn; GitHub is still a word.** `components/XGlyph.astro` is a hand-drawn X on the same 16-unit grid as the rest of the icon set, `currentColor`, one filled path, nothing fetched — `/privacy`'s list of what a page loads from elsewhere is a claim this site is built around, so a social logo arrives as geometry or not at all. It replaced the literal letter `X`, which is the one label here that could not do its job: a lone `X` in 11px mono reads as a close button or a multiplication sign long before it reads as a company. **`GitHub` has no such problem and stays a word.** That is not an inconsistency to tidy up later — *a logo earns its place when the word cannot be read*, and the octocat would be a filled silhouette in an otherwise monoline set, illegible at 14px, standing in for a word that was already working. The accessible name is `X` either way (`aria-label` on the anchor, since the glyph itself is `aria-hidden`), so the two rows say the same thing to a screen reader whichever way they are drawn. `social` in `components/Footer.astro` carries a `glyph` flag, and it is the only row with one.

**The mark is a double-struck X, which is not the X most people would draw.** Three strokes, not two: the `\` is a *ribbon* — two parallel walls closed by a flat cap at each end with a counter between them — and the `/` is a single stroke of the same weight crossing both walls, with the counter punching through it too, so the `/` breaks where it passes the ribbon and reads as running behind it. **Every end is cut horizontally**, parallel to the baseline rather than square to its own stroke, and that is why this one glyph is ink where the rest of the set is stroke: `stroke-linecap` offers butt and round, never a horizontal cut on a diagonal. `fill-rule="evenodd"`, so the counter stays a hole whichever way its points end up ordered.

Weight is **1.25 units perpendicular on all three strokes** — the number `ShotActions.astro` and `ThemeToggle.astro` set as `stroke-width`, spelled as ink instead of as a stroke, so the glyph sits at the weight of the moon two items along. The real mark is lighter than that against its own box (about 0.87 units at this scale) and read spindly beside a 1.25 stroke; 1.35 and up closed the counter at 14px. Both were rasterised at 1x before this one was picked, which is the same measurement `public/favicon.svg` is settled by. The angles are **not chosen**: both strokes run corner to corner of a 13-unit ink box, so the ribbon — two walls plus a counter wide — has to lie shallower than the single `/` to fit, 32.1 degrees off vertical against 41.1. The real mark is 34.5 against 40.7 for exactly that reason, and the small difference is our heavier stroke widening the ribbon. **An X drawn symmetrically here would be a different letter.**

Three of the four share one prose shell, `styles/global.css › .doc`, because pages that read as siblings must not each keep their own copy of the measure. **`/design` is the one that does not, and the reason is §5.** `.doc a` gives every link inside the shell the prose treatment, which is right for three pages that are paragraphs from top to bottom and wrong for a page whose sections are chips, swatches, specimen words and buttons. Sharing the class would have meant bolding and underlining a chip and then writing a rule to un-bold it, which is exactly the override §5 forbids. So `design.astro › .sheet` is scoped at `.doc`'s proportions, and its paragraphs opt into the prose-link rule **by being paragraphs** — `.sheet p a` is in the selector list in `global.css` rather than restated on the page, so /design cannot end up drawing a prose link the rest of the site has stopped drawing.

**`/design` has no markdown variant, and that is a judgement rather than an omission.** The `PAGES` machinery would make one cheap to add, but the document it produced would be a lie: the page's content is CSS and live components, and markdown can render neither a chip nor a swatch, so the variant would have to be prose transcribed by hand — the one thing `lib/markdown.ts` exists to prevent. The markdown version of this page already exists and is the file you are reading; `/design` links to it in the repository, and `/llms.txt` names both and says which is the source.

**900px is the palette's breakpoint**: below it the palette becomes a full-screen sheet. 599px and 639px exist to reflow list rows from three columns to a stack; 600px and 900px also step the entry title (§2) and 600px hides the bar's Search.

**The menu button** (`MobileNav.astro › .mnav__trigger`, VET-239) is a glyph, not a word: a 2×2 grid of **4px squares 3px apart** (an 11px `currentColor` SVG, `crispEdges`) centred in a **40px square**, 44px under `(pointer: coarse)`, `--text-secondary` at rest. Hover (gated, §4) fills it `--surface-3` at `--r-md` and lifts the ink to `--text-primary`. While the panel is open it swaps to an **X, 20px, 1.75px stroke, round caps**, off `[aria-expanded="true"]` in CSS; the script sets `aria-expanded` and swaps `aria-label` between "Open menu" and "Close menu", since the glyph has no text. The panel covers the trigger while open, so its own close button is what a reader presses; focus returns to the trigger on every close.

**The menu panel** (`components/MobileNav.astro`). The menu button at the left of the top bar opens a full-height `--accent-panel` sheet with the mat's `--grain` under a 35% veil of the same blue (white ink 4.77:1 on the lightest speck, VET-261), `min(86vw, 380px)`, mono items entering on a 70ms stagger after an 80ms lead-in; the actions row (search, then the theme toggle) continues the same stagger via `--search-i`. It is the section nav at every width since the dash rail went (VET-225). The **row** is what carries the entrance, not the controls in it. Closing sets every delay to 0 — nothing leaves on a stagger. Layers: the bar 30 (the panel's scrim 70 and sheet 80 stack inside it, above the page), palette 100.

**An open panel is modal to the keyboard, not just to the pointer.** `aria-modal` claims it; `inert` is what makes it true — without it, Tab walks off the last control in the panel and into the page behind the scrim, focusable and invisible. `setOpen` flips `inert` on every `[data-mnav-inert]` surface (the shell, the skip link, the bar's trail and Search — `layouts/Base.astro`, `TopBar.astro`, `Breadcrumbs.astro`) plus the trigger itself, and lifts it before handing focus back. The theme live region carries no marker on purpose: the panel's own toggle announces through it while the panel is open. The palette needs none of this because its focus trap is structural — the input is the only focusable control in it, and Tab is swallowed (§4). `lib/mnav.test.mjs` holds the wiring at both ends.

Every transition here is a **CSS transition, never a keyframe animation**, so an interrupted open/close reverses from wherever it is instead of snapping. `visibility` flips only after the slide-out finishes.

> **Never write a bare `<` in that file's frontmatter, comments included.** It makes the Astro compiler lose the `Props` interface when it generates TSX, and every prop silently stops being typed. `npx astro check` is what caught it, twice.

**Safe-area insets are written but not yet live, and the distinction is the whole point.** The three surfaces welded to a viewport edge carry `env(safe-area-inset-*)` guards: the palette's full-screen sheet takes `padding-top` (`styles/palette.css`, below 900px), the menu panel takes all four paddings through `max()` against its own `--mnav-pad` (`MobileNav.astro › .mnav__panel`), and the top bar takes its inline padding the same way (`components/TopBar.astro › .bar`). **All three resolve to `0px` today.** `env()` only returns a real number when the viewport meta says `viewport-fit=cover`, and `layouts/Base.astro` ships plain `width=device-width, initial-scale=1` — so iOS letterboxes the page inside the safe area, nothing is under a notch, and there is no bug on screen. `max()` was chosen over addition for exactly this reason: at zero it degrades to the number the design already asked for, so the guards are a no-op on the current build by construction rather than by luck.

They are written now because the change that makes them matter is **one attribute**, and the surfaces it would break first are a search field under a notch and a blue sheet stopping short of the home indicator. **`viewport-fit=cover` is not a one-line change, and must not be added as one.** It puts every edge-anchored surface into the unsafe zone at once, and the three above are not the whole list: `SiteMark.astro` sits at `left: var(--page-pad)` (24px floor, against a 44–59px landscape inset), the shell's own `--page-pad`, and `Base.astro › .skip`. Adding the meta means auditing those too, on real hardware in both orientations — §8 gate 7, and a simulator is not it.

**A row note *is* clamped in CSS, and the difference from a post tile is what sits behind it.** Every listing row on the site caps its note at **two lines** (`LibraryList.astro`, `LibraryPane.astro`, `ToolList.astro` on a phone (its desktop column is one truncated line, briOS's), the /library video tile's title in `LibraryViews.astro`, all `-webkit-line-clamp: 2`; `LibraryFeed.astro` keeps its TLDR to one ellipsised line; the /tools grid clamps a tile's name the same way, `ToolGrid.astro`), which is Aayush's call on the shipped lists: a /library note runs to 295 characters, because a saved post's note is the post's own first 280, and at that measure it is five lines under a one-line title. It hides at most three lines of a sentence that is already a summary, in a `<p>` that is not inside any link, on a row whose title goes to a page carrying the same note whole as its standfirst. **The video tile is that argument about a different medium, and the mechanic is `lite-youtube-embed`'s, hand-rolled** (`components/VideoFacade.astro`). **Every library entry has a page, and this paragraph used to say the opposite.** It read *"a library entry earns its page by being digested"*, and the rule under it was that a row's destination is the thing itself — no `/library/<slug>`, because a page holding one line and a button to leave is a stop on the way to the thing. **What changed is the entry, not the argument.** The stub the old rule refused does not exist any more. A saved link now arrives carrying tags (§1's dots, and every one of them a filter link), a saved post arrives carrying the whole post the row can only quote 280 characters of, and a saved video arrives carrying a poster somebody can press. That is a catalogue card, which is a real thing to be — every value on it goes somewhere, and the reader who wanted the piece itself is one press from it and knew that before they arrived. The old rule was refusing a page that would have held a line and a button; this one holds a line, a date, three filters and a door. Enrichment is what made the difference and it is not a one-off: the sweep tags and reads every new save, so a page thinner than this one is not something the pipeline can produce.

**A digest is still exactly what it was, and it is still the thing worth having.** `lib/library.ts › Digest` is unchanged, all four fields or none, and a digested page adds the cliff notes, the verdict and the why under labels (`DigestBlocks.astro`, labels from `lib/markdown.ts › DIGEST_LABELS`, held by `lib/digest.test.mjs`) plus a second date. Two dates on the strip on purpose, three when there is a draft: `saved` is when the link came in, `digested` is the day the verdict was last true, `drafted` is the day the pipeline had its go, and an opinion with an old date on it is a warning. `lib/library.ts › digested` is no longer the route table — `library` is (`library/[slug].astro`) — and what it still gates is §7's `Review` node and the Digests section of `/library.md`. **A page is not an opinion**, and that is the whole line the reversal moved: the page was standing in for the opinion, and now it does not have to.

**The TLDR is the lead** (VET-233): one sentence on what the source says, 20px in primary ink under the strip, never his opinion. **The middle of the page is optional blocks, ordered by what the reader came for** (`EntryDetail.astro`, shared with /library's Articles view): the thing itself when the site has it (for a post, `PostCard.astro` at `mode="page"`; for a video, `VideoFacade.astro` for the poster), then the piece's own words (`ReaderBlocks.astro`, VET-246: up to five highlights as pull-quotes under an accent-bar "Highlights", each an optional tertiary note beneath, then the excerpt quoted and cited), then his note, the digest, the draft, his own `why`, and on an article a 48px "Read the full article ↗" as the last word. **The site quotes a piece and never republishes it**: `lib/reader.mjs` caps the TLDR at 25 words, highlights at five of 60 words, the excerpt at 80, no em dash, and both the build and `pipeline/patch.mjs` hold those caps. **The highlighter** is a `mark` whose background is a gradient at `100% 100%` with `box-decoration-break: clone`, so each wrapped line gets its own stroke; amber by default, blue, pink or green by `data-color`. On a screen with motion allowed, and only where the pre-paint script set `data-theme`, it is armed at `0% 100%` and an IntersectionObserver releases it once at half-visible, a 600ms `--ease-out` sweep. No script, reduced motion and print all get the whole mark, and print keeps its colour with `print-color-adjust: exact`. Each is gated on its own field and renders nothing when it is null, which is §6's empty-labelled-box rule at entry grain. `lib/detail.test.mjs` holds the route table to `library` and every block to its gate, because a route that narrowed back to `digested` would leave forty rows pointing at a 404 and nothing else on the site would notice — the row renders, the graph validates, and the link is dead.

**A drafted block is the one thing on the site that is not him, and it is built to look it** (`DraftBlock.astro`). `lib/library.ts › Draft` is a separate type from `Digest` rather than a looser one, because folding them together is what would let an unearned opinion render in his voice. Three things keep them apart where a reader can see it: the draft is the only thing down an entry page sitting inside a border, its label is at **full ink** against the `--text-tertiary` every other label on the page takes, and its body stays in the third person under a sentence of his saying whose words these are. His own `why` renders through `VoiceBlocks.astro` — the component /tools and /sites draw his sentences with — and it renders **only** from the entry's top-level `why`, never from `draft.why`. That is a field move rather than a relabel: when he writes his own it lands on the entry and leaves the draft empty, and no rendering bug that drops a flag can swap the two, because there is no flag.

**A saved site shows its own design tokens, not only its pixels** (`SiteFoundations.astro`, VET-224). `pipeline/design.mjs › readDesign` runs one `page.evaluate` during the capture, after the walk-down, and reads computed styles off up to 1,500 visible elements: colours `background` (what shows at the page margins), `surface`, `text`, `text-muted`, `accent` (chromatic link or button colour), `border`; type `display` (h1), `heading` (h2, else h3), `body` (p), `label` (button, nav link), `mono` (code, only if present); the five most common spacing values (named on the 4px step, firecrawl.md's convention); and the three most common radii, named by the element they were seen on, plus `full` for a pill. Role names only, and a token is written only when something was seen doing that job (ui-skills `create-design-md/SKILL.md`, URL mode). The result lands on the `sites.json` entry as `design`, after `palette`, and `lib/design-md.ts › parseDesign` drops any malformed token rather than failing the build. On `/sites/<slug>` the panel sits under the facts table as a **closed `<details>`** (VET-242): its summary row names the groups inside ("Colors, Typography, Spacing"), so closed still says what opening gets you. It replaces the Palette row only when it names **three or more colours** (`SiteDetail.astro`): a thin read (type and spacing with a colour or two) keeps the pixel swatches beside the panel, so the page never shows less colour than the shot does. The panel: colours (every role `summarize` found, six at most), typography (an "Aa" in the site's family, capped at 48px, with a caption saying it falls back when the font is not installed; first 3 styles), spacing bars, 48px radius boxes, every value click-to-copy through `lib/copy-flash.ts` (shared with `PaletteRow.astro`), and "Copy as DESIGN.md", which writes the tokens as a ui-skills DESIGN.md. **Fallback:** a Firecrawl-captured shot has no DOM, so it has no `design`, and a site whose read found nothing keeps the pixel Palette row. Older entries were filled once by `node pipeline/backfill-design.mjs` (30 of 31; mikes.cv refused TLS). `PaletteRow`'s root is `.swatches`, never `.palette`: that is the command palette's fixed, hidden overlay in `styles/palette.css`, and the collision kept the row invisible from VET-31 until this fix.

**Feeds** (VET-230). RSS 2.0 at `/rss.xml` (every section) and `/notes`, `/library`, `/tools`, `/sites` + `/rss.xml`, newest 50 each, written by hand in `lib/rss.ts` (escaping, order and cap are `lib/rss.test.mjs`; RFC 822 days are `lib/date.ts › rfc822`, beside `isoDay`) from items `lib/feeds.ts` builds. **Home, under the index: "Latest"** (`index.astro › .latest`, rows by `components/EntryList.astro`). The five newest feed items across sections, so the list and the feeds cannot disagree about what is new: title in `--text-primary` (18px/500, underline on hover), then section and day under it in `--text-tertiary` with a drawn `·`, stacked at every width (side by side went ragged when a long title wrapped), each row a 40px target. A "Follow it all by RSS" link closes it. Not rendered when there are no items. `/index.md` carries the same five.

**Library was Reading, and the pipeline still is.** A third of the section is videos, so the reader-facing name moved and every public surface moved with it: routes, the sections manifest, `/library.md`, `/llms.txt`, the palette index, the JSON-LD `ItemList`, `/about`. `vercel.json` 308s `/reading`, `/reading.md` and `/reading/*` to their `/library` equivalents, and those three routes sit **above** the markdown-negotiation block on purpose, so an agent asking for `text/markdown` at the old URL is told the URL moved instead of being served the old document forever. Note that Vercel refuses `routes` and `redirects` in the same file, so a redirect here is a `routes` entry with `status: 308` and a `Location` header, not a `redirects` block. Inside `pipeline/`, the section key stays `reading`: it is the name of the Raindrop collection Aayush saves into (`Publish/Reading`), it is written into every published row of `pipeline/state.json`, and it is his to rename rather than this repo's. The translation happens on one line, `pipeline/state.mjs › galleryFor`.

**Sharp corners.** Every corner on the site is one of five values, and what carries each is written down. **`--r-sm` (4px)**: the focus ring, the video tile's play badge, the palette's `esc` key cap, inline code, a scratch note's thumbnail in a list (`EntryList.astro › .row__thumb`, 3px until the Wave A QA). **`--r-md` (8px)**: the tag, ui-skills' TopicTag `rounded-lg` taken whole (VET-219), a `pre`, a prose image, and the palette's highlighted row (concentric inside its 16px panel, below). **`--r-pill`**: the chips (`chip.css › .chip`, briOS's status shape since VET-225) the accent bar (`global.css › .accent-bar`) and the screenshot scroller's thumb (`ShotFrame.astro`): lozenges, not boxes. **`--r-lg` (12px)** is a state, never a frame at rest: the focus ring a /tools row draws (`ToolList.astro › .row__link::after`), and a /library pane row (`LibraryPane.astro › .pane a`), whose hover and `aria-current` fill it bounds. **0** is everything structural — frames, swatches, panels, the post card and the fallback inside it, the drafted box. That is the line: a rounded corner marks something you could pick up or are pointing at, never a surface you look through. The VET-222 grid card and its 8px border are gone (VET-227). The /tools app icons used to add a 6px and a 3px; since VET-226 they are a superellipse mask (`AppIcon.astro`), which is a shape rather than a radius, for the reason the next paragraph gives the monogram. The radius boxes in a site's design panel (`SiteFoundations.astro › .shape`) are not a sixth: their corners are the saved site's data, like a swatch's colour. A sixth needs a reason you can write down. **Two surfaces break the square-panel rule on purpose.** **The ⌘K palette panel is 16px** (G1, VET-247), swiped.design's `.cbox`: it floats over a blurred page as a modal rather than sitting in it, and below 900px, where it becomes a full-screen sheet, it is square again. **The hover preview card** (`PreviewCard.astro`, VET-228) takes `--r-md`, briOS's `rounded-lg` copied as specified. It floats over the list rather than sitting in the page, it is never focused or scrolled, and it is the only place a screenshot is shown at thumbnail size; if it should be square, it is one token to change.

**The monogram's `border-radius: 50%` is not another radius, and the word doing the work is *corner*.** `styles/chip.css › .monogram` is a circle, and a circle is a shape rather than a rounded rectangle: there is no corner in it to be concentric with anything, and no size at which it reads as a softened box. It is the avatar slot with a letter in it (§1), and an avatar is round everywhere a reader has ever seen one — squaring it to 4px would make the one element on the site that is standing in for somebody's face look like a chip with an initial in it. The scale above counts corners, and a circle adds none. The app icon's squircle is the same kind of exception: a continuous curve with no corner in it. It lives once, as `global.css › --squircle`, shared by `AppIcon.astro` and the palette's rows.

**Nested corners: outer = inner + inset** (craft's rule, borrowed rather than installed, VET-240). A rounded box inside a rounded box is concentric only when the outer radius is the inner one plus the gap between them; the same radius on both makes the gap fat at the corners and thin on the sides. In force at one place today: the hover preview card is `--r-md` (8px) with a 1px border, and its `overflow: hidden` clips the picture to 7px, which is the rule done by the browser. The /library pane rows are `--r-lg` in a square pane, so there is nothing to nest into. And at the palette: a 16px panel with 8px of list padding gives its rows 8px, `--r-md`.

## 4. Interactions

**Press.** `styles/global.css › .press` scales to `--press-scale`, default **0.96**, over `--dur-fast`. Wide elements dial it back rather than shrinking by 4%: full-bleed list rows use **0.995** (`index.astro › .row`, `notes/index.astro › .row`, `404.astro`) because a full-width row shrinking 4% reads as a glitch, not a press; A /sites tile has no press: its picture grows 2% on hover instead (VET-242, below), and a card that also shrank under the finger would be two motions for one click.

**That one is on the card and not on the bar's anchor, and the reason is mechanical rather than aesthetic.** The bar's anchor carries the stretched `::before` that makes the whole card a target, and an absolutely-positioned pseudo resolves `inset: 0` against its nearest positioned **or transformed** ancestor — so a transform on the anchor re-anchors the overlay to the bar for the length of the press, shrinking a target that already has a finger on it. Scaling the card is also the truer statement now that the card is the target. Nothing inside X's embed is ours to give a press state to, and `:active` does not cross an iframe boundary, so the embed never triggers it.

**Never `transition: all`.** Every transition names its properties, everywhere, without exception. Corollary: if an element already carries `.press`, do not add a second `transition-property` to it — the two race depending on stylesheet order (`ShotActions.astro › .act`, `EntryNav.astro › .hint`).

**Reduced motion** (`styles/global.css › prefers-reduced-motion`) flattens every animation and transition to 0.01ms, zeroes delays, kills `scroll-behavior: smooth`, and disables the press scale. What that global brake **cannot** do is two things, so components handle them:

1. It cannot undo a transform an element *rests* at. Anything resting on one restates it under `prefers-reduced-motion` (`styles/palette.css › .palette__panel`, `MobileNav.astro › .mnav__item`).
2. It shortens durations but leaves *entrance* delays meaningful. So a staggered entrance gates the whole animation on `prefers-reduced-motion: no-preference` instead (`SiteGrid.astro › card-in`) — otherwise a card sits invisible for its delay and then pops in.

**Keyboard, the palette** (`lib/palette.ts`). Cmd/Ctrl+K toggles from anywhere. Arrows move with wrap, Home/End jump, Enter follows, Escape closes. Tab is swallowed: the field is the only focusable control in an open palette, so swallowing Tab *is* the focus trap. Focus never leaves the input — the highlight is `aria-activedescendant` (`› setActive`). Focus returns to the opener, which is passed in explicitly rather than read off `document.activeElement`, because Safari does not focus a clicked button (`› setOpen`). Navigation assigns `location.href`; a synthetic `row.click()` on a subtree that is no longer rendered silently does nothing (`› const go`). The index arrives on first open (`› load`); a failed fetch says so in the empty line instead of claiming no matches, and the next open retries. The footer's sound toggle swallows `pointerdown` so a click on it leaves focus in the field.

**Keyboard, entry pages** (`components/EntryNav.astro › KEYS`). One component owns the hint row and the keys it wires, and two pages render it: a `/sites` entry and a `/library` entry. Escape closes to the section index, ← and → walk the entries in the order the section renders them — the gallery order on /sites, the list order on /library, which is also the list pane's order — wrapping, and a one-entry ring offers no prev and no next rather than two links to the page you are on. Destinations are read off the *visible* hint anchors, so the legend a reader can see and the behaviour a keyboard gets cannot drift: delete a link and the key goes quiet with it. Any modifier bails (Cmd+← is Back, and taking that over is a hijack), and so does a focused text field and a held key's repeats. **briOS's `k` and `j` (VET-231) fire only with focus inside the /library list pane** (`[data-pane]`): a bare letter anywhere else belongs to the reader's own shortcuts and speech input (WCAG 2.1.4), so on /sites, which has no pane, they do nothing. On `(hover: none)` the key caps (`.hint__key`) are hidden: no keyboard, so the words alone are the links. The pages decide only the ring and the words; the anatomy, the CSS and the handler live in the component, because the second page is what proved the row would otherwise be ninety lines kept in step by nothing.

**Precedence: an open palette wins.** Three surfaces listen for keys on `document`, and the order two document-level listeners run in is a bundling detail, not a guarantee — so none of them may depend on running first. Every other surface **asks the document** whether a palette is open: `MobileNav.astro` queries `[data-palette][data-open]`, `EntryNav.astro` queries `[aria-modal="true"][data-open]`. The palette sets `data-open` **synchronously**, which is exactly why `styles/palette.css` hides with `visibility` rather than `display` — visibility can still be transitioned off one synchronous attribute. The full note is the header comment of `lib/palette.ts`.

**Scroll chaining, the VET-32 lesson.** `overscroll-behavior: contain` is for **modals only**: the palette results and the mobile nav panel. Anything in the normal flow of a page states `overscroll-behavior-y: auto` and lets the page take over at either edge (`ShotFrame.astro › .scroller`). `contain` on a details page whose main content *is* the scroller is a trap — the reader hits the bottom of the picture, keeps scrolling to read the notes below it, and nothing happens until they physically move the pointer off the frame. Nothing looks broken; the page just stops answering the gesture it is built around, which is why this is a rule nobody re-derives by reading the CSS. `lib/overscroll.test.mjs` sweeps every shipped file under `src/` and fails on a `contain` outside those two, so a third one has to be a deliberate edit to that allowlist **and** to this paragraph.

**The theme toggle** (`components/ThemeToggle.astro`, state in `lib/theme.ts`). One button, three states, cycling system → light → dark → system. It renders twice — quiet in the footer beside the clocks, and on the mobile nav panel where the footer is a long scroll away — and the hoisted script drives every instance from one listener. 14px glyph in a 40px `::before` hit area, the same trick the footer's X glyph uses (`Footer.astro › .foot__link--glyph::before`), so a control with a toolbar's hit area does not put a toolbar's height into the footer row.

Three things are worth not re-deriving. **The glyph is swapped by CSS off `[data-theme]`, never by script**, because the attribute is written before the first paint and a JS swap would show a sun for a frame to everyone who pinned dark. **The accessible name is the half CSS cannot do**, so `aria-label` and `title` ship saying `system` — which is the truth with scripting off — and the module corrects them on load; the label names the current state *and* the next one, because `aria-pressed` cannot describe three states honestly. **One `aria-live` region for the whole page** (`layouts/Base.astro › [data-theme-live]`), outside the buttons, because text inside a control is that control's accessible name, and two regions would announce one change twice.

**The flip is a snap, and the whole page snaps together.** The background carries no transition, so it changes on the next paint — but every link, chip and quiet control names `color` in a `transition-property`, and without help those crossfade for `--dur-fast` after it: a page that snaps except for its words reads as a smear. So `choose()` suppresses every transition for the flip — inject `transition: none !important`, set the attribute, force a style flush so the new colours commit while the override still applies, drop it on the second `requestAnimationFrame`. One beat, and only on a press; the pre-paint script needs none of this because there is nothing painted yet to transition from.

**Hover is gated where the control keeps the page.** On touch, `:hover` latches after a tap and holds until the next tap lands somewhere else — which on a control that is still on screen reads as a stuck state. So the hover styles of the theme toggle (both variants), the shot actions, the menu trigger and the footer row sit behind `@media (hover: hover)`; the trigger's `[aria-expanded="true"]` ink is real state and stays outside the gate. Controls whose press unloads the page — rows, tabs, crumbs, chips — skip the gate, because the latch is gone before it could be seen.

**Hover is instant on anything a pointer sweeps across** (craft's rule, VET-240). A list row, a table row, a grid tile, a /sites card, a palette row and a /tools sort button change their fill, border or ink on the next frame, with no `transition`: moving down a list at speed with a 120ms fade leaves a trail of half-lit rows behind the pointer, and the one under it is never quite on. `LibraryPane.astro › .pane a`, `LibraryFeed.astro › .feed a`, `LibraryViews.astro › .vtile`, `ToolList.astro › .row` and `.sort`, `ToolGrid.astro › .tile__link`, `SiteGrid.astro › .card__link`, `SiteList.astro › .row`, `LibraryList.astro › .row`, `experiments.astro › .row`, `index.astro › .row__num` and `.row__name`, `palette.css › .palette__row`. Motion that is movement stays: the home index arrow slides 4px, `.press` scales, the preview card fades. The global `a` colour transition and the entry-page controls' hover band (below, thebridge) are not rows and were left alone.

**A delay belongs to the first tooltip in a group, never the rest** (craft's rule). The hover preview card is the only tooltip-like surface here and already works this way: it opens 300ms after the pointer arrives, and while one is open the next trigger swaps in at once (below). Anything that grows a hover card later takes the same shape: one delay per group, zero inside it.

**The hover preview card** (`lib/preview-card.ts`, styles in `components/PreviewCard.astro`, VET-228). briOS's `PreviewCard.tsx` in vanilla: hovering a /tools row, a /tools grid tile or a /sites list row shows the outside site, and the click still goes to our page (§5). One card node per page, built by the script on first use and appended to `body`; any element carrying `data-preview` is a trigger, and `previewAttributes` writes it (`components/tool-attributes.ts › toolAttributes` for rows and tiles, `SiteList.astro` for rows; a /sites gallery tile carries none, because the tile already is the picture). The numbers are briOS's: **opens 300ms** after the pointer arrives, **closes 100ms** after it leaves, and while one is open the next trigger swaps in at once. **Keyboard focus opens it too**, only on `:focus-visible` so a click's focus does not; Escape closes it and keeps it shut until the pointer or focus leaves that trigger; blur, a press anywhere and a scroll close it. **Touch never sees it**: every listener checks `matchMedia("(hover: hover) and (pointer: fine)")` and `pointerType === "mouse"`, so on a phone the node is never built. Placement is script, because Firefox's CSS anchor positioning is still partial (`placeCard`, tested in `lib/preview-card.test.mjs`): **8px below** the trigger, **flipped above** when it would cross the viewport floor minus **20px** and there is room above, **shifted** to stay 20px inside both sides, and centred on the cursor's x as it moves along a row (briOS's `trackCursorAxis="x"`); keyboard focus centres it on the trigger. Anatomy: **400px** wide (`min(400px, 100vw - 40px)`), a **40:21** picture `object-fit: cover` from the **top**, then a footer of domain (`--text-tertiary`, 14px), name (`--text-primary`, 15px/500) and the description and the note (`--text-secondary`, 14px, **two lines each**, the note dropped when it repeats the description), 1px `--hairline-strong` border, `--r-md`, `--bg`, and briOS's `shadow-lg` — the palette's register (§3): only a surface that floats over the page gets a shadow. **The picture is decoded before the card changes** (`Image.decode()`), so a slow file never flashes broken; a tool with no preview file shows a copy of its row's `AppIcon` at 40px beside the words instead. **Motion:** opacity plus `scale(0.96)` and a 4px nudge away from the trigger, origin at the cursor, 150ms in and 100ms out on `--ease-out`; reduced motion drops the transform. It is `position: fixed` and `pointer-events: none`, so it shifts no layout and never catches a click, and `aria-hidden`, because every word on it is already in the row. **Pictures:** a tool's is `public/previews/<slug>.webp`, a 1200×630 light-scheme viewport shot stored at 800×420 (the card's 2x) under 60KB, taken by `pipeline/preview.mjs` when the tool is published and checked on disk at build (`lib/assets.ts › assetFor`). **A preview is never a GitHub page**: the address comes from `icon.mjs › siteOf`, the same resolver the icon uses (the url, or a repository's own `homepage`, else a README link that is labelled or badged as the site or sits at the root of a host named after the repo or owner (`pipeline/readme-site.mjs`), and null for anything on a GitHub host), so a repository-only tool is the icon-only card. Sixteen repo-page shots, one of them showing a contributor's avatar, were deleted in the Wave A QA; a site's is its existing `/shots` capture cropped from the top. All self-hosted, so /privacy is unchanged.

**Pressing play is a press, and what follows it is the reader's** (`components/VideoFacade.astro`). The play control keeps the page, so its hover sits behind the gate above; a modifier bails to the browser, the same call `EntryNav.astro › KEYS` makes about Cmd and the arrow keys, so Cmd-click still opens the video at the source. Focus moves to the player once it is there, because the control focus was on has just stopped existing. **`autoplay=1` survives reduced motion on purpose**: the brake is for motion nobody asked for, and this is a video someone pressed play on. What reduced motion does govern here is the facade, which rests on no transform and waits out no delay.

**A press ticks** (`lib/ui-sound.ts`, VET-243, after builtbydesigners.com). A 24ms burst of seeded noise (fast attack, `exp(-t*255)` decay, a late thock at 4.5ms) through a highpass at 720Hz, a +3.5dB peak at 2350Hz and a lowpass at 7200Hz, gain .018, at most one per 35ms. It fires on a mouse or pen `pointerdown` and on keyboard activation (`click` with `detail === 0`) of any enabled button, link, field or summary; touch stays silent. The /sites panel opens a little lower (`playbackRate` .85) and closes a little higher (1.15); `tick({ rate })` is the export for later cues. The `AudioContext` is made on the first press that would sound, never on load, and never while muted. **Off by default under reduced motion**, on otherwise; the footer's speaker button (`SoundToggle.astro`, `aria-pressed`, beside the theme toggle) and the palette's "Sound" row flip it, persisted as `localStorage["ui-sound"]`.

Nothing is written to local storage until a press. `/privacy` names every key: the theme, the /tools and /sites view, the click sound (`localStorage["ui-sound"]`, VET-243), and the library list pane's scroll, which is `sessionStorage` and written without a press (it is only a position, and the tab forgets it). Anything else reaching for either storage has to go and edit that page.

**Analytics is one deferred tag, and it is same-origin.** `layouts/Base.astro` ships `<script is:inline defer src="/_vercel/insights/script.js">` behind `import.meta.env.PROD`, not `@vercel/analytics/astro`. The component's job is to register a custom element that re-fires a pageview across *client-side* route changes, and a static site with no client router has none, so the bare tag counts the same loads without the dependency or the bundled module. Both URLs it touches are paths on this domain — the script, and the `/_vercel/insights/event` beacon — added to the deployment by Vercel's edge once Web Analytics is on for the project. **That is the whole reason counting page views added no host to `/privacy`'s list**, which makes it the claim to re-check before changing how analytics loads: a script that starts arriving from a Vercel host is a new host, and `/privacy` names it in the same commit. The package only reaches `va.vercel-scripts.com` in debug mode, which is development-only and not what this tag loads. The `PROD` gate is because the route exists only on a deployment: under `astro dev` it 404s on every page load, which teaches you to ignore the console in the one workflow §8 tells you to verify in.

**The ink floor: interactive ink never sits below `--text-secondary`.** `--text-tertiary` is metadata's colour. Since VET-225 it clears AA (4.74 / 5.28), but it is still the level a reader skims past, so a control sits one level above it at `--text-secondary` (7.81 / 9.96) and never reads as a label. The rule was already written into this file once — §3's kind tabs, "a control has to clear AA on its own" — and these are the surfaces that had not caught up: the colophon links and the footer Search (`components/Footer.astro › .foot__quiet`), the bar's Search (`components/TopBar.astro › .bar__search`), the quiet theme toggle (`ThemeToggle.astro › .tt`), the shot actions (`ShotActions.astro › .act`), the /tools sort buttons (`ToolList.astro › .sort`), the domain link and the source link on a /library row (`LibraryList.astro › .row__domain`, `› .row__source`), the experiment links (`experiments.astro › .row__links`), the collection links on /sites (`sites.astro › .collections a`, VET-223), the tag counts on the /library filter row (`styles/chip.css › .tag__count`), the hint row (`EntryNav.astro › .hints__row`), the strip anchors (`tools/[slug].astro › .strip a`), the host link under a library entry's title (`library/[slug].astro › .out a`), the 404's agents line, and the palette's empty state. Static metadata — dates, group heads, captions, the `esc` cap, separators, the copyright — stays `--text-tertiary` on purpose: it is the layer below the page's voice, and lifting it would flatten the hierarchy the two tokens exist to draw. `lib/ink.test.mjs` recomputes both composites from the tokens in `global.css` and holds the fixed selectors at `--text-secondary`.

**Hit areas: 40px floor.** The bar's menu button is a 40px square (44px under a finger); its crumbs and Search are 40px tall by padding (`0.625rem` over a 22.4px line), swatches are 44×44 (`PaletteRow.astro › .swatch__chip`), a design-panel token row is 40px tall (`SiteFoundations.astro › .row`), the mobile close is 44×44, shot actions set `min-height: 40px`, and the footer's X link gets 40×40 the same way the theme toggle beside it does (`components/Footer.astro › .foot__link--glyph::before`) — offsets rather than a centring transform, so nothing rests on one and reduced motion has nothing to undo. A tag chip takes the same trick on an `::after`, `0.375rem` past a 28px chip and horizontal only, because a wider box would swallow presses meant for the row beside it; `TagChips.astro` then keeps wrapped lines `0.75rem` apart, so adjacent targets may touch, never overlap.

**A row of those chips has to be as tall as the chips and no taller, and for one build it was not** (VET-114). Aayush, reviewing the filter row: the line spacing looks weird. The row gap was not the culprit and could not be — it *is* the hit area, and it cannot go below twice the chip's overreach without one line eating presses meant for the next. The extra air was a **line box**: an `li` is a block box and a `.tag` is `inline-flex`, so every chip sat on a text baseline inside a strut as tall as the inherited line-height. Measured live on `/library`, on the chip of the day: a 20.27px chip in a 25.59px item, 5.32px per line that nobody chose and no number in the stylesheet accounted for, and a pitch of 45.59px for a chip 20.27px tall. `display: flex` on the item blockifies the chip and the strut has nothing to hold — **pitch 40.27px**, and what is left between two lines is the row gap and only the row gap. The column gap went `0.4rem` to `0.5rem` in the same pass, because 6.4px across was tighter than a chip's own side padding under 20px down. `lib/tags.test.mjs` holds the gap against the overreach and the item against the line box, since the second one is invisible in the source: every number reads correctly and the row is simply looser than all of them say.

**The gap and the chip height are one arithmetic.** A 40px target on a chip of height *h* laid out with a row gap *g* needs `h + g ≥ 40`: at the tag's 28px that is `g ≥ 0.75rem`, which is the row gap `TagChips` and `TagFilters` use, with ui-skills' `gap-2` (`0.5rem`) across. **The kind chip on a `/library/<slug>` strip claims 40px too** (`library/[slug].astro › .strip__chip::after`), `0.62rem` past its 20.3px box, because the tags on its line do and §4's text exception does not cover a box.

**A hit area is only as good as the line under it, and that strip is where it went wrong.** `.strip` inherited `gap: 0 0.7rem` from the /tools strip it was copied from, where nothing claims more room than it draws. Wrap that row and the tag's overreach (then `0.62rem`) lands on the line before it: measured at 375px, the first tag's target covered the kind chip by 9.9px and the domain link by 8.6px, and on a digested entry at desktop width it reached down over the `digested` date, so pressing a date opened a tag page. The row gap is `1.25rem` now — twice the kind chip's `0.62rem`, the larger overreach on that line — with a `0.5rem` column gap. **Since VET-223 the tags are the strip's last item and take a line of their own at every width** (`.strip__item--tags`, `flex-basis: 100%`, no separator): in the middle of the row they wrapped as one block on a phone, indented under their own `·`, which then sat alone to the left of them, and the date after them opened the next line with another. Now the row is one line of facts and one row of subjects, and the `1.25rem` between them is the kind chip's `0.62rem` reach plus the tag's `0.375rem`, with room over. `lib/tags.test.mjs` holds the gap against the larger overreach, so a chip that grows its target has to grow the line with it. One stated exception: the entry-page hint rows use `padding-block: 0.5rem` instead (`EntryNav.astro › .hint`), because those are text hints and a 40px block would give the foot of the page a toolbar's weight. **The footer's text links take that exception too** — `GitHub` and the four colophon pages are words in a row of words, and 40px blocks around them would put a toolbar's height into the foot of every page. The floor is for targets that are only a glyph.

**The thebridge reference, and what was taken from it.** Aayush pointed at noahfarrar.com/thebridge for the feel of an entry page, and it was mined off its live DOM rather than described: body 14px/18.2 at `-0.14px` tracking, H1 also 14px, dates 12px mono, field labels 10px at 50% ink, rows 46px hairline-separated, page ground `rgb(250,250,250)` against a white card, hovers at 150–300ms, category labels fading in on row hover. It is a custom build, so every number transfers literally and the question is only which ones should.

**Adopted: the hover band.** Entry-page controls move from `--dur-fast` to `--dur` (`library/[slug].astro › .strip a`, `› .strip__chip`), which is 220ms and inside their 150–300. A row in a list of forty keeps the fast one — a pointer is crossing it, not resting on it — and a metadata strip on the page you have stopped on is the other case. The chip's opacity step was outside any transition and snapped while the two links beside it faded; it now shares the band.

**Adopted: the density, arriving as the note clamp.** Their compactness is mostly a 46px row, and the equivalent here was a listing row three to five lines deep. §3's two-line cap is that change, made where it belongs.

**Adopted a second time, on the post block** (VET-114, carried into `PostCard.astro` by VET-244): the name's tracking is `-0.01em`, and the name and handle sit as one stacked unit beside the avatar with no gap between them.

**Refused, each to a rule already in this file.** The 10px labels and 12px mono dates stay at the label voice, **14px** (11px until VET-223, 13px until VET-225): §2's label voice is one size everywhere, and a page with its own smaller one is a second voice, not a tighter version of the first. The 14px body stays at **17px** on a post's own page (`PostCard.astro › .pc--page`): that page exists to be read, and its measure and leading were the whole argument for it in VET-61. The lifted card on a tinted ground stays **hairlines on `--bg`**: the site has one way of separating things and a shadow is a register it does not use anywhere, the same call the palette made about their frosted scrim. And **reveal-on-hover metadata is refused outright** — a value that only appears on hover does not exist on a phone, and every value on that strip is a filter link.

Both size refusals came up again on the post block in VET-114 and both were kept, which is what a ledger is for: a refusal that has to be re-argued every time it is inconvenient is not recorded, it is just deferred. The post block also stays **unseparated** — no hairline above it — because `DigestBlocks`, `VoiceBlocks` and `DraftBlock` all separate by top margin alone, and a fourth block on that page ruling itself off would be the only one.

**Focus.** `styles/global.css › :focus-visible` is 2px `--accent`, offset 3px, radius `--r-sm` (`--r-md` on a tag, whose ring follows its 8px box). It flips to `--accent-panel-ink` on the blue panel, and on the screenshot scroller the frame *is* the ring (`ShotFrame.astro › .scroller:focus-visible`). The palette input sets `outline: none` on purpose: it is the only focusable control in an open palette, so a permanent ring would be furniture rather than a signal, and the highlighted row is the cursor.

## 5. Links

**Prose links are blue and underlined, at body weight.** A 2px underline 2px below the baseline in the accent at 40% (`color-mix`), solid accent on hover (VET-225; briOS draws the line in his quaternary grey, we keep our accent). Scoped to where prose actually lives: `.prose a, .doc a, .sheet p a, .standfirst a, .voice__body a, .source a, .fact dd a:not(.chip)` (`styles/global.css`). `.sheet p a` is the one entry keyed to the paragraph rather than the container, because /design's shell holds specimens as well as prose and those have to be exempt structurally — see §3. The 600 weight went when prose moved to `--text-primary`: a bold blue word in a near-black paragraph shouts. The line is the cue that does not depend on seeing colour.

**Exempt surfaces are exempt structurally, not by an override.** The top bar, chips, footer items, index rows, tool and library rows, tab links, hint rows and metadata strips are simply **not in that selector list**, and each sets its own `text-decoration: none`. Underlining them would turn navigation into a paragraph of shouting. Do not extend that selector unless the link sits inside a sentence, and do not "fix" a nav link for missing an underline.

Furniture that still needs to read as a link uses the quiet pattern: inherited or `--text-secondary` ink — never below `--text-secondary`, which is §4's ink floor; a quiet anchor inside a `--text-tertiary` container states `color: var(--text-secondary)` rather than inheriting a metadata colour — with an underline in `--hairline-strong`, going `--accent` + `currentColor` on hover (`LibraryList.astro › .row__domain`, `tools/[slug].astro › .strip a`). It carries its own underline because on touch there is no hover to reveal one.

**The exemption in that selector list is a `:not()`.** A quiet-pattern anchor sets a colour and an underline; it does not think to set `font-weight`, because nothing on it looks like it is asking for one. So a container in the prose list catches it and it ships at 600 having visibly opted out. `:not(.chip)` is the structural exemption; a `font-weight: 400` on the page would be the override this section forbids. **Adding a furniture anchor inside `.source`, `.fact dd`, or any other prose container means adding it to the `:not()`, not restyling it locally.**

**A tool has two links and they are different kinds of thing.** `url` is the product's own site and `repo` is its GitHub repository (`lib/tools.ts › Tool`), and a repository written into `url` **fails the build** — `readUrl` refuses it by name, because that one conflation is what put a column of identical GitHub logos on /tools and hid the real site of every tool that had one. Either may be null; half the list is software whose only home is a repository. What counts as a repository is one function, `lib/links.ts › githubRepo`: exactly two path segments on github.com, canonically spelled, so a profile, a branch, a file, a gist and a release are all refused. The publish pipeline keeps its own copy because it runs outside the bundler (`pipeline/entries.mjs › repoFrom`), and `links.test.mjs` holds the two to the contract that matters — whatever the pipeline writes, the parser accepts unchanged.

**A row links the tool's page; the page links out** (VET-227). A /tools row or grid tile goes to `/tools/<slug>`, never off the site (hovering one shows the outside site in the preview card, §4): the row is where a reader compares, the page is where they decide, and the page is the one place both destinations sit side by side. The Source line at the foot of a details page is the way out: `Website ↗` for the product's own site and `GitHub ↗` for the repository, each when it exists, both when both do (VET-241). Words, not two full URLs, so they read as two kinds of place rather than a choice. A repository that moved after the verdict says `GitHub (moved)` (`repo_moved: true` in the entry). Each `·` is a `::before` on the second wrapper span, never on the anchor, per §6 (`tools/[slug].astro › .source__link`). `/tools.md` keeps linking the product in its table, because an agent reading markdown wants the destination, and lists every details page under it.

**The /tools and /sites mark is an app icon, `AppIcon.astro`: a live logo.dev logo over a self-hosted icon over the letter** (VET-254). `lib/links.ts › markFor` gives three layers. The top one is `img.logo.dev/<domain>?size=64&retina=true&fallback=404`, loaded live because logo.dev's free plan does not license keeping copies; the domain is `url`'s host (`logoDomain`), never a github.com or github.io host (the octocat), and an entry's `logoDomain` field overrides it: a hostname when the site sits on the wrong brand's domain, `null` when logo.dev draws a screenshot, a social card, a face or a parent company (17 tools and 5 sites carry `null` from the VET-254 contact sheet). On that image's `error` a one-line inline handler swaps it once to `/icons/<slug>.webp` and, if that fails too, removes it. The letter tile is always rendered under the picture in the same grid cell, so a failed logo costs no layout shift and ships no script. The image carries `referrerpolicy="strict-origin-when-cross-origin"`, so logo.dev learns the site, not the page. **img.logo.dev is the only outside host on /tools, a tool page and /sites, and /privacy names it.** The `/icons` files come from `pipeline/icon.mjs`, once per tool, when the publish pipeline adds it (backfill: `node pipeline/icon.mjs`): the site's apple-touch-icon, then the largest web-manifest icon, stored as a 256px WebP on white, and never a logo.dev image. Sources under 120px are refused, because the largest mark is 60px and 120 device pixels at 2x. **The shape is Apple's continuous corner**: a superellipse (n = 5, 96 points) applied as a CSS `mask`, so it scales with the box, with a 0.5px ring in `--outline` made by excluding a 1px-smaller copy of the same mask. It is **32px in the table and 60px in the grid** (`ToolList.astro`, `ToolGrid.astro`; `--icon-size` on an ancestor still overrides the `size` prop) and 16px beside a details page's Source line, where only a picture draws (`letter={false}`: with none left the tile hides). The icon is decorative (`aria-hidden`, `alt=""`) because the name is always beside it, and `draggable="false"` with `user-select: none`. **The letter tile is the monogram in a squircle**: `.monogram` supplies the hue fill and ink off `hueSlot(slug)`, AppIcon replaces the circle and scales the type to 0.43 of the edge. **It will not use a GitHub avatar.** `github.com/{owner}.png` is a stranger's face at 28px for most owners here, or a generated identicon, which is not identity; `icon.mjs` refuses GitHub image hosts and `markFor` never asks logo.dev about a GitHub host (it answers with the octocat), so a repository-only tool gets a picture only when the repo names a site of its own (its `homepage`, or a strict README match, VET-241). A found site is saved to the entry's `url` and `repo` is kept. **A new image host on a page means editing /privacy in the same commit.**

**/tools is briOS's /stack: a sortable table, URL filters, and an app-icon grid** (VET-227). **The table** (`ToolList.astro`) is a real `<table>`: Name (32px icon and name), Description (`tool.description`, falling back to `note` until that field is filled), Category, Verdict (the tinted pill), Date (`formatDay` in `<time>`, no "As of"). **It is briOS's /stack table in everything but the outer padding** (VET-239, `StackPageClient.tsx`): edge to edge inside the frame (it bleeds out of the shell's padding and pads its outer cells back by `--page-pad`, so the dividers and hover reach the frame and the names line up with the title), 14px text on a 20px line, rows `12px` top and bottom (57px with the 32px icon and the divider), `--hairline` dividers (.09 in both themes), a `--surface-2` hover, the name at 500 on one truncated line, the description in `--text-tertiary` on one truncated line. Columns are Name 27%, Category 9.5rem, Verdict 7.5rem and Date `6.75rem + --page-pad`, Description taking the rest, at every width. It matched briOS's `grid-cols-12 gap-4 px-4` to the pixel from 1280px until VET-255 moved the outer padding to 48px: a one-twelfth track inside that is narrower than a date ("Aug 17, 2026" is 88px) until well past 1600px, so the twelfths went and the fixed widths that already ran below 1280 took every width. Name, Category, Verdict and Date are `<button>`s inside their `<th>`, and the `<th>` carries `aria-sort`; a press cycles the column's natural direction (A to Z, verdict rank using first, newest date first), the reverse, then file order (`lib/tools-table.ts › nextSort`, briOS's cycle). Below 640px it stays a table and loses columns rather than changing `display` on a `tr` or `th` (which strips table semantics in Safari): Description, Category and Date hide, header and cell together, so the accessibility tree has two column headers and two cells per row; the description reappears inside the name cell (`.row__desc--phone`, shown only there, two-line clamp), so each width exposes exactly one copy. The verdict and category pages render the same table with their subset and drop the column their h1 already states (`drop`), the way a /library domain page drops its domain. **The filters** are two native `<select>`s, Verdict and Category, defaulting to All, synced to `?verdict=&category=` by a client script on `pages/tools.astro` (the site is static): a change `pushState`s, `popstate` re-reads the URL, so Back steps through the filters a reader tried, and a value not on the page reads as All. Filtering sets `hidden` on rows and tiles; the count beside the selects ("N tools") is `aria-live="polite"`, and a combination with no match shows an empty line with a link back to all. `lib/tools-table.test.mjs` holds the cycle, the sort and the query round-trip. **The grid** (`ToolGrid.astro`) is an iOS home screen ruled in hairlines (VET-257): a 60px squircle and the name centred under it at 13px/500, in cells padded 20px top and bottom, 3 across below 600px, 4 to 767, 6 to 1023, 8 to 1439 and 10 from 1440, each tile one link to the details page. The link fills its cell inside the lines, so the `--surface-2` hover (instant, square) and the focus ring (inset 2px) stop at the rule. Those surfaces are a directory: the reader is scanning a list of destinations, and a new tab is right because they are coming back to the list.

**The arrow is not part of that treatment, and this paragraph has now been rewritten twice.** It first said the arrow rode with `rel` and `target` on every off-site anchor, which a grep disproved: `.ext` shipped on the four prose links and on the Source line at the foot of a details page, and on **no list row and no card**. The reasoning that fitted was that on a page where every row leaves, forty arrows say nothing. The paragraph then closed by naming the one case that would change it: *"the one place the arrow would carry information is /library, where some rows leave and some go to a detail page — so if it ever comes to a list, it comes to that list"*.

**VET-63 is that case arriving, and it arrived from the other direction.** Every /library title goes to a detail page now, so no row leaves by its title and the arrow would still be saying nothing — but the row keeps one link out to the source (`LibraryList.astro › .row__source`), and that one is the only anchor in the list that ends the visit. One arrow on one control per row is the whole information the old paragraph was holding the convention for: it separates the door from the three filters beside it. So `.ext` comes to that list, on that link and on nothing else.

**VET-67 gave the card an outbound anchor after all, and it took the arrow with it.** That sentence used to end here by saying the card had none, which was true while the card was one link to a page on this site. The card is X's embed now, and the permalink at the foot of its fallback is both the id their factory reads and the one control there that ends the visit — the row's situation exactly, one component over, so it gets the row's answer: `.ext`, `rel="noopener nofollow"`, `target="_blank"`. The `notes` bar beside it wears none of the three, because it goes one page further in rather than out, and it draws a plain `→` instead. One arrow of each kind is the anatomy; two of the same would be the ambiguity.

**Where a row, a card or a tile's title goes is one function, `lib/library.ts › entryHref`, and it no longer branches.** It returns `/library/<slug>` for every entry, because every entry has one. `LibraryList.astro`, `LibraryFeed.astro`, `PostWall.astro`, the video tile in `LibraryViews.astro` and `lib/search-index.ts` all read it, which is the point of it being a function rather than a template literal typed out five times: one of them would end up pointing where the others stopped.

**It used to return `{ href, external }` and now returns a string**, which is the same reversal one level down. The flag earned its place while half the answers were off-site — it decided `rel="noopener nofollow"`, `target="_blank"` and the arrow together, and a caller re-deriving "is this off-site" from a string is a caller that can get it wrong. With every answer on this site the flag is false everywhere, and a ternary in three components that can only take one branch is not a decision. What replaces it is one unconditional outbound anchor per row: the `source` link names its own `rel` and `target`, exactly as the play control on a video tile already did. **That play control still does not read the seam** — it points at the entry's own `url`, because the seam answers where a *title* sends a reader and the thing you press play on is at YouTube either way. `lib/schema.ts › libraryRowUrl` is the graph's copy, kept separate only because nothing in `schema.ts` may import a data module's runtime (§7), and `lib/card.test.mjs` holds the two to one answer and the row to exactly one door.

Three kinds of anchor sit outside it, and all three are prose.

- **Identity links**, at `rel="me noopener"` — `rel=me` is a claim of identity, so only real resolvable profiles go there. That is the two footer rows on every page, and the same two profiles written out as prose on `/contact`, which carry `.ext` on top because those two sit inside a sentence *and are still destinations*: sending the reader to them is what that page is for.
- **His own properties that are not identity claims** (the takedown-issue link on `/privacy`) keep `rel="noopener"` without `nofollow` — nofollowing your own profile is self-sabotage, and the anchor is an instruction, not an endorsement.
- **Citations in `/privacy`'s prose take `rel` and nothing else.** No `target="_blank"`, no `.ext`. The four of them — Vercel's analytics policy, logo.dev, Buttondown, and the GitHub issue above — are provenance rather than destination: they are the receipt for a claim the sentence just made, and most readers will never follow one. Four arrows through a page of paragraphs read as decoration, and forcing a new tab on someone reading a document top to bottom is the browser deciding for them what `back` should mean. **The distinction that governs all three: an arrow and a new tab are for a link the reader is being offered, not for one that is evidence.** Leave these as they are; adding `.ext` to a citation is the kind of tidying that makes a page worse.

**`mailto:` is not an off-site anchor.** No `.ext`, no `target`, no `rel`: the arrow means "this leaves the site for another page", and a mail client is not one. The single `mailto` on the site is `contact.astro › .mailto`, which is the index-row idiom instead — full bleed, hairline top and bottom, arrow on hover. **Its `href` is entity-encoded, every character of the address, and it has to stay static attribute text**: built from a template expression, Astro escapes the ampersands and the page ships literal `&amp;#97;`. `scripts/validate-schema.mjs` greps every built page for the plain address, `lib/schema.ts › contactJsonLd` emits no `email`, and the visible text says "Email me" and never the address itself.

## 6. Copy

Applies to everything a reader sees: data notes, standfirsts, blurbs, labels, alt text.

**Everything has to earn its place. Writing exists for the reader, not to show its work.** A sentence whose job is to prove the thinking happened is a sentence the reader is paying for and not receiving. Cut it. The three shapes this takes here: narrating the page's own construction ("I keep the rules in one file and the site in another, and this page is the second one showing its work"), qualifying a true statement until it reads as a disclaimer ("I co-founded Orbis. I am not the one running it"), and foreclosing a future to sound principled today ("the answer is no before you ask it, and it is still no the second time"). Accuracy without defensiveness: **"co-founded Orbis" carries the whole truth**, and copy is there to build a reader's confidence rather than to manage liability. `PURPOSE.md` at the repo root is the check, and it is short on purpose.

**Audit voice stays in audits.** "State the call", "the reasoning is", "four of these were set that way and quietly did not hold" — that register belongs in `qa/`, in an audit file, in this document. Never on a page. A page reports what is true; the file that got it there reports how it was decided.

**The voice guide is required reading before any copy change**, including a one-word one. It is `feature-research/aayushmanchanda-com/voice-guide-for-site.md` in the AayushOS repo, extracted from the gbrain page `voice-guide` (built from Aayush's own transcribed speech, texts and approved emails). It carries the register rule the web needs — the guide's baseline is his *spoken* voice, and site copy uses the written registers filtered through the improved layer, so no "bud", no "right?", no scene-grounding openers — and the invariant core that must survive: warm-direct, forward-looking close, self-aware wink, plain emotion. Motivational tone without the wink is instantly fake. One aphorism per page maximum, and it has to feel found.

- **First person, present tense.** "Things I actually installed and ran, with an honest verdict" (`lib/sections.ts › CATALOGUE`). "Killed experiments stay on the page, because deleting them would make me look better than I am" (`experiments.astro`).
- **Plain words.** No *leverage*, *seamless*, *powerful*, *journey*, *delve*. The bar is the tools data: "Lost the same head-to-head to Cabinet on my use case."
- **Real opinions only.** A verdict is a judgement someone can disagree with. `watching` plus "Saved from Raindrop. Not tested yet." is the honest placeholder the pipeline writes; anything stronger has to be earned by actually running the thing.
- **Honest dates.** Every opinion carries the ISO date it was last true — `status_date`, `saved_date`, `started` — rendered beside it as `Aug 13, 2026` in a `<time>` (`lib/date.ts`), because an opinion with an old date on it is a warning.
- **Verdicts as prose, not a template.** Five fields, each a sentence in his voice: `note`, `why`, `like`, `dislike`, `try`. Absent means absent — a null field renders no block, and a caller with nothing at all renders nothing (`VoiceBlocks.astro › blocks`). An empty labelled box is worse than silence: it reads as a page that failed rather than a tool he has not written up yet. A /library digest follows the same rule at a different grain: the whole object is optional and its four fields are not (`lib/library.ts › readDigest`), because bullets with no verdict are a summary, and the verdict is the point. Digest copy is site copy — his voice, real calls, `Parked` said plainly — and `digested` is its honest date.
- **No em dashes in new copy.** Use a period, a colon or a comma. *Known deviation:* five notes in `data/tools.json` written before this rule still carry one. Fix on touch; do not add more. The `sites.astro` standfirst and the `sites/[slug].astro` shot caption were the sixth and seventh and were fixed the next time copy was touched, the `sites/collection/[slug].astro` lead the eighth before them — which is what the rule means. The tool notes are dated verdicts, so their turn comes when a verdict is actually re-formed, not on a copy pass.
- **A line break next to a tag is not a space. It is nothing.** Astro drops the whitespace at a text/tag boundary when it contains a newline, so an anchor that starts its own line comes out welded to the previous word: `about it.\n<a href="/privacy">/privacy</a>` ships as `about it./privacy`. A newline *between two plain words* still collapses to a space, and a break *inside* a tag is harmless — it is only the boundary that bites, which is why the source always looks right. **Keep the space on the same line as the tag**, and break inside the opening tag when the line gets long. Two of these were live on `/privacy` for months. `scripts/validate-schema.mjs › GLUED` now fails **CI** on either half of the pattern — the validator reads `dist/` and runs as its own step, so it is not the build that catches this (§8).
- **Separators are drawn by CSS, never typed into content.** The `·` between metadata items is a `::before` on the list item, outside the anchor, so it is never part of a link's text or its target (`tools/[slug].astro › .strip__item + .strip__item::before`). The footer was the one place still typing them — five `<span aria-hidden="true">&middot;</span>` in `.foot__meta`, which is also what forced that row to be a `<p>` of loose anchors instead of a list — and now draws them (`components/Footer.astro › .foot__meta li + li::before`). It uses the alt-text form, `content: "\00b7" / ""`, which is what preserves the `aria-hidden` those spans were carrying by hand. **Four more have joined it on touch** — `library/[slug].astro › .strip__item` and `EntryNav.astro › .hints__item` first, then `tools/[slug].astro › .strip__item` and `sites.astro › .collections__row` in VET-223, the commit that next opened those files — which is what "on touch" means. Every drawn separator on the site now has no accessible name. Where a row wraps on a phone, the dots go: `.foot__meta` under 600px and `.collections__row` under 640px drop the pseudo-element and let a wider flex gap (`1rem`) separate, because a dot that travels with its item can start or end a wrapped line either way.
- **Alt text says what the picture is of**; decorative marks take `alt=""`. *Stated exception:* a picture attached to a saved post (`PostMedia.astro`) gets `Picture 2 of 4 attached to the post by Ben Lang`, which says what it **is** rather than what it is of. Nothing here has looked at it — the pipeline copied a file, and the alternative is a sentence about a picture nobody read, which is worse than an honest label. Not `alt=""` either: it is the post's own content and a reader who cannot see it should still know how much of the post they are missing. If these ever get described, they get described from the picture. *Second stated exception:* a video's poster frame takes `alt=""` (`VideoFacade.astro`), which is the decorative case rather than an exception to it — the control lying on top of it is already named `Play video: <title>` and the title is a line below, so describing the still would be one name read out three times.

## 7. Structured data

Every page carries one `application/ld+json` block, and every node in it is built by `lib/schema.ts`. Nothing else on the site writes JSON-LD. `layouts/Base.astro › jsonLd` types the prop as `JsonLd`, so the only thing a page can hand the layout is something a builder returned — there is no route by which a page hand-writes a node.

**The parity rule is the whole contract: every property maps to something a reader can see on that page.** It is §6 applied to the machine-readable copy, and it is enforced in three places — the builders, `lib/schema.test.mjs`, and `scripts/validate-schema.mjs`, which reads the built HTML rather than the source that produced it. Only the first of the three fails a plain `npm run build`; the other two are gates that have to be *run*, which is why they now run on every push (§8).

**No ratings. Not one, not anywhere.** No `reviewRating`, no `aggregateRating`, no `ratingValue`. A verdict here is a sentence someone can disagree with, and there is no number on the page to carry into one. The cost is stated rather than discovered: Google's Review rich result *requires* `reviewRating`, so these reviews will never draw stars. That is the trade — a citable, honest claim instead of a decorated, invented one. Also absent for the same reason: `keywords` (nothing here is a keyword list) and `SearchAction` (the palette is a client-side filter, not a query endpoint, and advertising a search URL that 404s is a lie a crawler finds out about).

**And no `email`, which is the parity rule pointing the same way from both ends.** `/contact` does not print the address as text, so nothing on it may claim the address as text; and the encoding in that `mailto:` href is worthless the moment a graph hands the plain string back somewhere easier to read than the markup. `email` is in `FORBIDDEN` in both the validator and `schema.test.mjs`, and the validator also greps every built page for the address itself — the key is banned, and so is the value under any other key.

| Page | `@graph` |
|---|---|
| `/` | `WebSite` + `Person`, the site naming the person as both `author` and `publisher` |
| `/about` | `AboutPage` + `Person`, the page naming the person as its `mainEntity` |
| `/contact` | `ContactPage` + `Person`, same shape, compact `Person`, and **no `email`** |
| `/design` | `WebPage`, one node, `name` and `url` and nothing else |
| `/privacy` | `WebPage` + `BreadcrumbList` (`Aayush Manchanda / Privacy`) |
| 404 | none, on purpose — the reasoning is written in `lib/schema.ts`, after `privacyJsonLd` |
| `/tools` `/sites` `/library` `/experiments` `/notes` | `ItemList` |
| `/tools/<slug>` | `SoftwareApplication` + `Review` + `Person` + `BreadcrumbList` |
| `/sites/<slug>` | `WebPage` (`about` the external site) + `ImageObject` + `BreadcrumbList` |
| `/library/<slug>`, digested | `Review` (`itemReviewed` nested: the external piece, typed by its kind) + `Person` + `BreadcrumbList`, `datePublished` the digest's date |
| `/library/<slug>`, everything else | `WebPage` (`about` the external piece, typed by its kind) + `BreadcrumbList`, `dateCreated` the saved date, `description` the note when there is one |
| `/notes/<slug>` | `Article` + `Person` + `BreadcrumbList` |
| filter pages | `ItemList` + `BreadcrumbList` |

**A `BreadcrumbList` is the trail the top bar prints, item for item**: `Aayush Manchanda / Section / Page`, three items with home first (`lib/schema.ts › breadcrumb`, `HOME`). The bar reads it back through `trailOf` rather than being handed a second copy, so the two cannot drift. It was two items, no home, while the visible crumb was a lone `← Tools`; the bar made home a visible link, so the graph gained it. Section indexes and the colophon pages print a two-step trail and carry no `BreadcrumbList`: a trail of home plus the page itself describes nothing a search engine can use. `/privacy` is the exception, by the Wave A QA: it was the one indexable page with no graph, and it got the node and the trail the bar already draws.

**A `/library/<slug>` page has two shapes and the digest is the whole difference, which is the parity rule deciding a `@type` rather than a property.** Every entry has a page (§3) and most of those pages carry no judgement at all, so typing them all `Review` because the route used to only build reviews would put a machine-readable verdict on forty pages nobody has read. A page with no digest emits a `WebPage` instead: `about` the saved thing typed by its kind, `dateCreated` the visible saved date, `description` his note and nothing when there is no note. It emits **no `Person`**, which is the call `siteJsonLd` already makes — nothing on that page is attributed to him in the graph, so a `Person` node would sit in it referenced by nothing.

**A drafted block reaches the graph in no form at all.** It is his pipeline's placeholder, and the page labels it as one in a bordered box at full ink because a reader can be told; a graph cannot. There is no property in schema.org that means "somebody's agent wrote this and nobody has checked it", and the nearest available ones — `reviewBody`, `description` — would all quietly launder it into a claim. So a drafted page is a `WebPage` exactly like an undigested one, and `schema.test.mjs` serialises the graph for a fixture that carries a draft and fails on any of its sentences appearing anywhere in it. `scripts/validate-schema.mjs` splits the same two shapes into two page types over one URL pattern (its `PageType.when`), so a digested page that quietly stopped emitting its `Review` fails the build rather than passing as the other kind.
**`/design` is the parity rule at its shortest, and the reason the validator grew a second axis.** The page is a specimen sheet: its content is CSS and components rather than text, it has no byline, no date and no image, so its graph is one `WebPage` carrying a name and a URL. That collided with `scripts/validate-schema.mjs › REQUIRED`, which held every `WebPage` to the five properties a `/sites` entry has. So `REQUIRED` is now what is true of a type **everywhere** (`WebPage`: `name`, `url`) and `EXPECTED[].requires` is what is true of it **on one page type** (a site details page's `WebPage` still owes `about`, `primaryImageOfPage` and `dateCreated`). A shared type held to one page's shape is a rule that fails the second page to use it.

Five things are worth not re-deriving.

**Every document is an `@graph`, even a one-node one**, so the validator and anything reading the built HTML walk one shape. **A `{"@id": …}` reference must resolve inside its own graph** — a parser reading one page cannot follow a reference to a node that only exists on another — which is why the `Person` is repeated on every page that attributes something to him, and absent from every page that does not. **That `Person` is compact off the home and about pages**: `name`, `url`, `sameAs` and nothing else, because those are the three things the site mark and the two `rel="me"` footer rows make visible *everywhere*, while the biography is only visible on those two. `/about` gets the long form because it is the home page's hero at length; `/contact` does not, because it prints no biography. **The opinion never leaks onto the thing being reviewed** — a `SoftwareApplication` gets name, url, category; every judgement lives in the `Review`, attributed and dated. Its `url` is the destination the Source line actually offers, which is the repository when there is no product site, and `sameAs` carries the repository **only when it is a second page** — never the same URL twice under two properties, which would claim a source that is not there. **`lib/schema.ts › pageUrl` must agree with the canonical link**, because Astro builds directory-format routes and `/tools/paperclip` vs `/tools/paperclip/` is two URLs for one document; the validator compares the two on every built page. **The 404 has neither, and that is the rule rather than an exception to it** — it is served at whatever URL the reader mistyped, so the `/404/` it is built at is not its address. It ships `<meta name="robots" content="noindex">` and omits `rel=canonical` and `og:url` entirely (`layouts/Base.astro › noindex`, the only caller). Pointing them at `/` was the alternative and is worse: it claims the error page is a duplicate of the home page, which is a different false statement rather than a fix.

`serialize()` escapes `<`, `>`, `&` and both line separators. The block goes out through `set:html`, so a note containing `</script>` would otherwise end it early and put the rest of the graph into the document as markup.

## 8. Before you ship UI

**Gates, all of them, every time.**

**The first three run on every push and every pull request** (`.github/workflows/ci.yml`). They were a list a person was trusted to run, which is discipline, and discipline is what goes first on the day a change looks too small to bother — so they are a machine's job now. Run them locally anyway: CI is the backstop, not the loop. The last four cannot be automated and are still yours.

1. `npx astro check` → **0 errors, 0 warnings.** Hints have a known baseline of 13 (eleven `z is deprecated` from `content.config.ts`, one unused `Props`, one unreachable-code hint); do not add to it. Note that `checkJs` is on, so a new `.mjs` under `scripts/` or `pipeline/` is type-checked too and needs its JSDoc. **CI cannot hold the hint baseline for you** — `astro check` exits 0 on a hint, so a fourteenth passes the step and only the count in the log says otherwise.
2. `npm test` → all pass (544 at the time of writing).
3. `npm run build` → clean, then `npm run validate:schema` → clean. The second reads `dist/`, so it is only meaningful after the first, and it is a separate CI step for the same reason: a failure should name which of the two broke.
4. **Both themes, and both forced states.** Four looks, not two: OS light, OS dark, and then a pinned theme fighting each of them — `data-theme="dark"` on a light OS is the one that catches a token declared in only one of the two dark blocks. Every colour is a token; a hex outside `styles/` is the bug.
5. **Mobile.** At 375px: the top bar's trail (a long title ellipses, ancestors never do) and the menu panel, the row reflows at 599/639, the palette as a full-screen sheet.
6. **Reduced motion.** Turn it on and look again. Nothing resting on a transform may be left displaced; nothing may sit invisible waiting out a stagger delay.
7. **Live verification against the real page.** `npm run dev`, open it, and press the thing you changed. Reading the built HTML is not verification.

**Already in force. Do not regress these.**

- **Image outlines.** Every image sitting on the page background carries a 1px inset outline (`styles/global.css › .outlined`) so a white screenshot is not a hole in a white page. It is craft's 10% rule, and the carriers are: a /sites frame and its scroller (`ShotFrame.astro`), a /sites gallery card (`ShotFrame.astro › .crop`), a note's figure (`ImageFrame.astro`), post pictures and Article covers (`PostMedia.astro`, `PostCard.astro`; a `<video>` is focusable, so it takes none), a video poster (`VideoFacade.astro`), a note thumbnail (`EntryList.astro`), an app icon (`AppIcon.astro`, a drawn ring because the squircle is a mask), and a markdown image (`prose.css › .prose img`, the declaration rather than the class, since markdown cannot put a class on an `<img>`). The hover preview card's picture is the one image without it: the card's own border is its edge on three sides and a hairline is the fourth. `--outline` is pure black at 10% in the light theme and pure white at 10% in the dark one, never a tinted near-black: a tinted outline picks up the surface under it and reads as dirt on the image edge.

  **It is a real `outline` at `-1px` offset, and it shipped for months as an inset `box-shadow` that never painted.** An inner shadow is drawn above an element's background and below its content, so on an `<img>` — content is the picture, and there is no padding to leave a gap — the ring is drawn and then covered. Eight of the nine things wearing the class are images, so the rule was doing nothing on all eight; the ninth is a `<span>` (`ToolList.astro › .row__mark--initial`), where it worked, which is why a repository tool's initial had an edge and the favicon rows away from it did not. **Nothing caught it because absence looks like nothing**: the failure of an outline is a missing hairline, and no page looks broken without one — it surfaced by putting a white image on the white theme and looking for its edge. `ShotFrame.astro › .scroller` had already worked out half of it, stating a real outline because "a shadow is painted under the element's own children"; what nobody generalised is that a replaced element's picture is that child, one level down. The scroller is not an exception any more. `lib/outline.test.mjs` holds the property, and holds the class off anything focusable — it sits after `:focus-visible` in `global.css` at the same specificity, so an `.outlined` control would lose its ring.
- **`text-wrap: balance` on headings, `pretty` on paragraphs.** Already global. Do not re-declare per component.
- **Stagger etiquette.** Entrance staggers cap: `SiteGrid.astro › STAGGER_CAP` is 8 at 80ms, so card forty is not waiting three seconds; nav items are 70ms after an 80ms lead-in. Nothing staggers on the way out.
- **Reserve the box.** An image whose size is not known at build time gets its box from `aspect-ratio` or a fixed scroller height, never from absent `width`/`height` attributes (`ShotFrame.astro`). **Two crops, both anchored `top center`**, because the top of a screenshot is the half that says what it is: **8:5** for a /sites gallery card (`ShotFrame.astro › .crop`), **40:21** for a site's screen strip and the preview card (`SiteDetail.astro › .screen__shot`), briOS's, and **16:10** for a post tile's media (`PostCard.astro › .pc--grid > .pm`). A post's own pictures carry their source `width` and `height`, so their boxes are reserved from the attributes.

  **16:9 is not a second crop** (`VideoFacade.astro › .tile__frame`). 8:5 is the answer for a picture whose shape nothing knows; a video's shape is known, and cropping its frame would cut the picture the video is actually made of. It is anchored `center` rather than `top center` for the same reason, and it is what makes the swap invisible: the player lands in the box the poster was already holding, so nothing moves when you press play. Both stored poster shapes fit it exactly — `maxresdefault` is 1280x720, and the `hqdefault` fallback is 480x360 carrying the same 16:9 frame letterboxed inside it, measured at 45 black rows top and bottom, which `cover` at the centre takes back off.

  > **`aspect-ratio` loses to a box's automatic minimum size, silently.** A flex or grid item's `min-height` is `auto`, which resolves to its content — so a ratio computes a height and then the content overrules it, and nothing warns. **This shipped**: four 1200px-tall screenshots came out 484px deep in a box that had asked for 208, and the card looked plausible enough that only measuring it in the browser found it. `min-height: 0` is needed at **both** levels — on the grid itself, which is a flex item of the card, and on the pictures, which are items of the grid. `VideoFacade.astro` states it at both of its levels for the same reason: the frame is a flex item of the tile, and the poster is in flow inside the frame.
- **Optical over literal.** A 16-unit icon set at 14px sits at the weight of the 14px label beside it instead of shouting over it (`ShotActions.astro › .act__icon`).
- **A control that cannot work is not shown.** The copy-image button renders hidden and reveals itself only once the page has established the browser can actually do it (`lib/site-detail.ts › canCopyImages`). A control that looks live and fails on press is worse than an absent one.

  The newsletter is the same rule one step earlier, at build time rather than on load. `lib/site.ts › NEWSLETTER_ACTION` is one string, `null` until there is a Buttondown account to post to, and `NewsletterSignup.astro`'s **entire template is a single expression guarded on it** — so an unconfigured newsletter is not a hidden box or a disabled field, it is no markup at all. **The copy on `/privacy` is gated on the same string**, both directions: the paragraph naming Buttondown only exists when the form does, and the sentence "no accounts, no forms, no comments, no newsletter box" only exists while it does not. That is §6's honesty rule applied to a page that would otherwise be truthful today and wrong on the day someone fills in a const. Activation is that one line and nothing else, which is why the home page places the component unconditionally (`index.astro`) and `lib/newsletter.ts` — not the markup — owns the field names Buttondown requires. `lib/newsletter.test.mjs` parses both `.astro` files and fails if anything renders outside a gate. The form is a plain POST that a script enhances, never replaces: pressing Subscribe tries a `fetch` first and confirms in place, and **any response that is not a clean success falls back to submitting the form natively** — Buttondown's docs say the subscriber sometimes has to see and follow the response, and their CAPTCHA and validation pages are only reachable by navigation, so the fallback is the contract and `newsletter.test.mjs` asserts `form.submit()` sits in the failure path. Scripting off degrades to the same native POST. The things that do ship while the newsletter is off are the component's scoped CSS and its script, inlined on the home page and finding nothing to act on, because Astro collects both from a page's imports rather than from what rendered.
