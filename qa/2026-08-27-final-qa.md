Eighteen accepted findings, all applied on 2026-08-27 and verified against a
real build and a running dev server. Seven were fix-now, eight were nice-to-

## Adjudicated extras (3)

- [x] **16. `urlKey` tracking denylist** in `entries.mjs`: `utm_*` as a prefix
      (that family is open-ended) plus `fbclid`, `gclid`, `ref`, `ref_src`,
      `si`, `igshid`. **A denylist, not a wholesale strip** — `youtube.com/
      watch?v=` carries its identity in the query, and stripping it would fold
      every video ever saved onto one key. The query is rebuilt whether or not
      anything was dropped, so `?q=a%20b` and `?q=a%20b&si=x` cannot survive as
      two keys through re-encoding. Docblock now names what happens to the
      query **and what the pre-existing whole-key lowercasing costs**: two URLs
      differing only in the case of a value collapse into one, which for `?v=`
      means two YouTube IDs of the same letters in different case. Accepted and
      written down rather than left to be rediscovered. 6 tests.
- [x] **17. Overscroll guard test.** `lib/overscroll.test.mjs` sweeps every
      shipped file under `src/` and fails on `overscroll-behavior: contain`
      outside the two modals (`palette.css`, `MobileNav.astro`). §4 has carried
      the VET-32 lesson since it happened, but `contain` is one word, is the
      more considerate-looking of the two values, and the bug is silent — the
      page simply stops answering the scroll. **Verified against a planted
      violation**, which it caught and named. Test files are excluded from the
      sweep: this one talks about the property it looks for.
- [x] **18. Sweep cosmetics.** The 404 claimed
      `rel=canonical` and `og:url` of `/404/` — the path it is *built* at, not
      the one it is *served* at. It now ships `<meta name="robots"
      content="noindex">` and omits both. **Pointing them at `/` was rejected**:
      that claims the error page is a duplicate of the home page, a different
      false statement rather than a fix. One new layout prop, `noindex`, with
      the 404 as its only caller. `robots.txt` cannot do this job — it allows
      everything on purpose, and disallowing a path stops a fetch, not an index.
      **/privacy: exclusion documented, node not added.** A `WebPage` there
      would carry `name` and `url`, which `<title>` and the canonical already
      say; §7 does not emit a node so a page looks complete. Reasoning written
      at the foot of `lib/schema.ts`, beside the builders whose absence it
      explains, with the note that /design is the nearest call and why it went
      the other way. design.md §7's table points at it.
